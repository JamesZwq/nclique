│ Step 2: Tree-Free R1 Peeling via Dual CSR                                    │
│                                                                              │
│ Problem                                                                      │
│                                                                              │
│ R1 ST (NCliqueVertexCoreDecompositionST.cpp) accesses tree.adj_list[leafId]  │
│ at 4 locations:                                                              │
│ - Line 66: count pivotC/keepC per leaf → leafRemainPivots, leafNeedPivot     │
│ - Lines 82-99: build Vertex→Leaf CSR                                         │
│ - Line 105: countingPerVertex (which internally traverses all leaves again)  │
│ - Line 238 (peeling): iterate leaf vertices to apply delta — the critical    │
│ one                                                                          │
│                                                                              │
│ // Line 238: needs leaf→vertex iteration                                     │
│ for (auto &node : tree.adj_list[leafId]) {                                   │
│     if (!vertexInHeap[node.v]) continue;                                     │
│     double delta = node.isPivot ? deltaPivot : deltaKeep;                    │
│     countingV[node.v] -= delta;                                              │
│ }                                                                            │
│                                                                              │
│ Solution: Dual CSR                                                           │
│                                                                              │
│ Build two CSR indices during Augmented SDCT construction (Step 1's           │
│ callback):                                                                   │
│                                                                              │
│ Vertex→Leaf CSR (for Phase 1: find affected leaves):                         │
│   vtxLeafOff[v] → vtxLeafOff[v+1]: range in vtxLeafData[]                    │
│   vtxLeafData[i] = {leafId, isPivot}   // 5 bytes per entry                  │
│                                                                              │
│ Leaf→Vertex CSR (for Phase 2: broadcast delta — replaces tree.adj_list):     │
│   leafVtxOff[L] → leafVtxOff[L+1]: range in leafVtxData[]                    │
│   leafVtxData[i] = {vertex, isPivot}   // 5 bytes per entry                  │
│                                                                              │
│ Both CSRs are built in a single pass during the Augmented SDCT callback. The │
│  callback emits entries into temporary buffers; after SDCT completes,        │
│ convert to CSR via prefix-sum + scatter (standard CSR construction,          │
│ O(Σ|leaf|)).                                                                 │
│                                                                              │

│ Step 4: Interleaved Construction-Decomposition (Exploratory)                 │
│                                                                              │
│ Idea                                                                         │
│                                                                              │
│ During SDCT construction with degeneracy ordering, vertex v (the first keep  │
│ vertex in each top-level BK call) processes all its subtrees before vertex   │
│ v+1 starts. After vertex v's subtree is fully explored, v is moved to X — no │
│  future leaf will contain v.                                                 │
│                                                                              │
│ This means after vertex v's subtree completes, countingV[v] is finalized. If │
│  countingV[v] ≤ current min-core, we can peel v immediately.                 │
│                                                                              │
│ Why This Is Theoretically Interesting                                        │
│                                                                              │
│ This transforms nucleus decomposition from a two-phase algorithm (construct  │
│ then peel) to a single-phase streaming algorithm. The asymptotic complexity  │
│ doesn't change, but:                                                         │
│ 1. Working set size decreases — vertices peeled early free their CSR entries │
│ 2. Cache pressure decreases — only "active" vertices are in memory           │
│ 3. Enables online/streaming nucleus decomposition for dynamic graphs         │
│                                                                              │
│ Correctness Argument                                                         │
│                                                                              │
│ From SDCT.cpp:154-177:                                                       │
│ for (int vertex = 0; vertex < n; ++vertex) {                                 │
│     keepV.push_back(vertex);                                                 │
│     recursive(..., keepV, dropV, tree);                                      │
│     // After return: all leaves containing vertex have been emitted          │
│     // vertex will never appear in future leaves                             │
│ }                                                                            │
│                                                                              │
│ After vertex v's recursive call returns:                                     │
│ - countingV[v] = final support value (no more leaves will add to it)         │
│ - All leaves containing v have their metadata stored                         │
│ - It's safe to peel v if countingV[v] ≤ minCore                              │
│                                                                              │
│ But peeling v subtracts delta from other vertices' support — those vertices  │
│ may still gain support from future leaves. So we need:                       │
│ - Track which vertices have "finalized" support (all their leaves emitted)   │
│ - Only peel finalized vertices                                               │
│ - Defer delta application to non-finalized vertices                          │
│                                                                              │
│ Implementation Sketch                                                        │
│                                                                              │
│ SDCT_Interleaved(edgeGraph, s, r,                                            │
│     [&](Size leafId, span<int> keepV, span<int> dropV) {                     │
│         // ... same as Step 2 callback: update support, build CSR entries    │
│ ...                                                                          │
│     },                                                                       │
│     [&](int vertex) {                                                        │
│         // Called after vertex's subtree is complete                         │
│         // vertex's support is now finalized                                 │
│         vertexFinalized[vertex] = true;                                      │
│         if (countingV[vertex] <= currentMinCore) {                           │
│             peelQueue.push(vertex);                                          │
│         }                                                                    │
│         // Process peel queue: peel all finalized vertices with support ≤    │
│ minCore                                                                      │
│         while (!peelQueue.empty()) {                                         │
│             auto v = peelQueue.top(); ...                                    │
│         }                                                                    │
│     });                                                                      │
│                                                                              │
│ Challenges                                                                   │
│                                                                              │
│ - Peeling v reduces neighboring vertices' support, but those neighbors might │
│  not be finalized yet                                                        │
│ - Need to handle the case where a non-finalized vertex's support drops below │
│  minCore due to delta from peeling                                           │
│ - May need a "pending delta" mechanism                                       │

  All datasets show >50% peelability during construction, confirming the
  interleaved approach is theoretically viable. The denser email-Eu-core graph
  shows higher peelability (85-88%) because degeneracy-ordered vertices finalize
   their support earlier. com-dblp at s=4 shows the lowest at 54.2%, still above
   the threshold.

  The probe uses a conservative lower bound (no early-peeling delta cascades).
  Real interleaved peeling would achieve higher rates because early-peeled
  vertices reduce neighbors' support, enabling more peeling.

  However, implementing the full interleaved approach requires solving the
  "pending delta" problem: when a non-finalized vertex's support drops due to
  peeling a finalized neighbor, we need to defer that delta until the
  non-finalized vertex's support is complete. This adds significant
  implementation complexity for modest gains — the peeling phase is already only
   ~10ms on com-dblp (7% of total runtime), so even perfectly eliminating it
  would save <10ms. The main benefit would be working set reduction for
  memory-constrained scenarios.

  Recommendation: Document as promising future work. The 2.45× peeling speedup
  from Steps 1-2 (tree-free dual CSR) is the high-value contribution.
  Interleaved peeling is architecturally interesting but offers diminishing
  returns given peeling is no longer the bottleneck.

  Algorithm Novelty Analysis

  Algorithm 1: CPI-ST (r=1 Immutable-Tree Peeling) — 
  NCliqueVertexCoreDecompositionST

  What it does: Immutable tree + per-leaf integer counters (remainPivots,
  needPivot). No tree mutation during peeling; delta computed via nCr difference
   formula when pivots are removed.

  Novelty:
  - Existing nucleus decomposition work (Sariyuce et al. SIGMOD'17) uses
  explicit s-clique enumeration + tree mutation. CPI (this codebase) avoids
  s-clique enumeration via the succinct degeneracy clique tree (SDCT).
  - The immutable-tree peeling with per-leaf counters appears to be new 
  engineering within the CPI framework — prior CPI implementations mutated the
  tree.
  - The nCr-based delta formula for batch peeling (handling Case A: leaf death,
  Case C: pivot-only removal) is a new contribution that avoids re-enumerating
  affected r-cliques.

  Speedup: 6–15x over Correct reference.

  Algorithm 2: CPI-ST-V2 (Tree-Free R1 Peeling via Augmented SDCT) — New in this
   work

  What it does: Fuses support counting, vertex→leaf index construction, and
  leaf→vertex index construction into a single SDCT callback. The tree
  (DynamicGraph<TreeGraphNode>.adj_list) is never materialised. Peeling uses
  flat dual CSR instead.

  Novelty:
  - Callback-based SDCT (SDCT_Augmented_NoTree): inject arbitrary computation at
   leaf emission time — a new abstraction over BK-based clique tree
  construction.
  - Tree-free peeling: eliminates 3 redundant O(Σ|leaf|) post-SDCT passes by
  fusing into construction.
  - Dual CSR for bipartite iteration: Vertex→Leaf CSR (for Phase 1: find
  affected leaves) + Leaf→Vertex CSR (for Phase 2: broadcast delta). Flat CSR
  gives ~2.8x better cache performance than vector-of-vectors.
  - Split Build/Peel architecture: SDCT runs before graph mutation
  (beSingleEdge), peeling runs after — a clean separation of concerns.

  Speedup: 2.3–4.8x over ST (the previous best).

  This is the strongest single contribution for a paper.

  Algorithm 3: CPI-ST-V4/V11 (r≥3 Immutable Peeling with Fast-Path Case 
  Extraction)

  What it does: For r≥3, when removed vertices are all pivots (Case C), computes
   delta via closed-form nCr formula instead of full BK re-enumeration. ST_V11
  adds batch bucket moves and compact clique-leaf IDs.

  Novelty:
  - Case A/C extraction avoids BK entirely for the dominant case (>90% of
  leaf-clique interactions are Case A: leaf death, or Case C: pivot-only
  removal).
  - V11's batch bucket move defers swap-pop updates to end of iteration —
  reduces random access on bucket arrays.

  Speedup: 1.5–2.3x over ST for r≥3, up to 3.2x on com-youtube r=4.

  Algorithm 4: Local H-Index (Local_V1–V4)

  What it does: Iterative H-index convergence instead of peeling. Each
  iteration: for each vertex, gather neighbor supports, compute H-index. Repeat
  until convergence.

  Novelty:
  - Applies the local H-index framework (Lu et al. PVLDB'18) to CPI-based
  nucleus decomposition. This is known in theory but the CPI integration is new.
  - V3/V4 add OpenMP parallelism. V4 uses async in-place updates.

  Performance: Much slower than peeling (10–100x slower than ST) on single
  thread. The value is only in multi-threaded scaling for very large graphs.

  总背景

  现有 SOTA 分为两条路线：
  - Sariyüce (SIGMOD'17)：显式枚举所有 s-clique，建立 r-clique 之间的 support
  关系，再 peeling。瓶颈在于 s-clique 枚举的指数级代价。
  - Jain/CPI (WSDM'20)：用 Succinct Degeneracy Clique Tree (SDCT) 隐式表示
  s-clique，通过 keep/pivot 分类避免显式枚举。但原始 CPI 实现在 peeling
  阶段仍然有大量冗余：树结构被反复修改、hash set 查找、BK 重新枚举等。

  我们的全部工作是在 CPI 框架之上，针对 r=1、r=2、r≥3
  三种情况，分别从理论（算法层面的新设计）和工程（数据结构 / 缓存 /
  批处理层面的优化）两个维度提出创新。

  ---
  R=1 (Vertex Nucleus Decomposition)

  创新 1：不可变树 + 整数计数器 peeling（CPI-ST）

  理论创新：

  原始 CPI 的 peeling 在每轮删除顶点后，需要修改树（tree.removeNbrs()、tree.recy
  cleNode()）并重建受影响叶子的 support。我们证明：对于 r=1，树结构在 peeling
  期间完全不需要修改。关键洞察：

  - 每个叶子只需维护两个整数：remainPivots（剩余 pivot 数）和 needPivot（构成
  s-clique 还需多少 pivot）。
  - 删除一个顶点 v 时，v 参与的叶子分为两种情况：
    - v 是 keep vertex：叶子直接死亡（leafDies = true），delta =
  当前叶子的全部贡献 = nCr[remainPivots][needPivot]
    - v 是 pivot vertex：remainPivots--，delta = nCr[old_rp][np] - 
  nCr[new_rp][np]（差分公式）
  - 因此只需 O(1) 的 nCr 查表而非树修改即可计算每个叶子的 support 变化量。

  工程创新：

  1. Vertex→Leaf flat CSR 索引：替代原始的 treeGraphV（robin_hood hash set per
  vertex，~40B/entry）为紧凑的 CSR 数组（~8B/entry），将 Phase
  1（定位受影响叶子）的 cache miss 降低 5 倍。
  2. 批量 bucket move（deferred dirty
  tracking）：先标记脏顶点，一轮结束后统一执行 bucket 迁移，减少 bucket
  数组的随机访问。
  3. Prefetch 优化：在遍历 CSR 时对下一个顶点的数据做
  __builtin_prefetch，隐藏内存延迟。

  创新 2：无树 peeling + 增强型 SDCT 回调融合（CPI-ST-V2）— 核心贡献

  理论创新（三点）：

  (a) Augmented SDCT — 回调式构建抽象：

  SDCT 的 BK 递归在到达叶子时，拥有完整的 keepV（keep 顶点集）和 dropV（pivot
  顶点集）。原始实现将这些信息存入 tree.adj_list
  后立刻丢弃上下文。我们引入一个回调接口：

  SDCT_Augmented_NoTree(Graph, max_k, min_k, onLeaf)

  在每个叶子生成时调用 onLeaf(leafId, keepV, dropV)，允许调用者在构建时就完成
  support 计算和索引构建。这是对 BK 枚举框架的一个通用扩展，不局限于 r=1。

  (b) 三遍冗余扫描→零遍融合：

  原始 CPI 在 SDCT 构建完成后需要 3 次 O(Σ|leaf|) 的全量扫描：
  1. treeGraphV 构建（vertex→leaf hash index）
  2. countingPerVertex（初始 support 计算）
  3. vtxLeafOff/vtxLeafData CSR 构建（flat 索引）

  我们将这三遍全部融合进 SDCT 回调，在叶子生成时同时完成 support 累加和 COO
  buffer 填充，构建后一次转换成 CSR。
  - 时间复杂度：从 T_sdct + 3·O(Σ|leaf|) 降为 T_sdct + 1·O(Σ|leaf|)
  - 不再需要 tree.adj_list 存储。

  (c) Dual CSR 替代树 + hash set：

  用两个紧凑 CSR 阵列替代 tree.adj_list（vector-of-vectors）+ treeGraphV（hash
  set per vertex）：
  - Vertex→Leaf CSR：Phase 1（定位受影响叶子）用
  - Leaf→Vertex CSR：Phase 2（广播 delta）用，替代 tree.adj_list[leafId] 的遍历

  空间从 ~53B/entry 降到 ~16B/entry，3.3 倍空间缩减。更重要的是，flat CSR
  的顺序访问模式对 CPU cache 极其友好。

  工程创新：

  1. Split Build/Peel 架构：SDCT_Augmented_NoTree 必须在 beSingleEdge()
  改变图结构之前运行，peeling 可以在之后运行。通过将 Build 和 Peel
  拆分为两个独立阶段解决。
  2. AugCtx 函数指针跳板：避免在深层 BK 递归中使用 std::function（每帧 ~128B
  开销导致栈溢出），用 void(*)(void*, ...) 函数指针 + void* userData
  实现零开销类型擦除。
  3. keepV == max_k 特殊处理：原始 SDCT 在 keep 数等于 max_k 时只存储 keep
  顶点（不存 pivot），回调需传空 dropV 以保持语义一致。

  R=2 (Edge Nucleus Decomposition)

  创新 3：Case A/C 闭式 delta 公式 + 合并遍历（CPI-ST for r=2）

  理论创新：

  r=2 的 peeling 删除边 (u,v)，受影响的叶子中边的角色分为三种 Case：
  - Case A（叶子死亡）：某个 keep 顶点被移除，叶子内所有 s-clique
  包含关系失效。delta = 全部贡献，可通过 nCr 公式直接计算。
  - Case B（边对冲突）：被删除的两个 pivot 之间的边冲突，需要 BK
  重新枚举子叶子。
  - Case C（仅 pivot 移除）：只有 pivot 被移除，叶子仍存活但 support 减少。delta
   可通过 nCr 差分公式精确计算，不需要 BK。

  关键定理：Case B 在实际图中占比很低（实验中 0.3%–3.6%），绝大多数是 Case
  A（>90%）和 Case C（<10%）。因此用闭式公式处理 A 和 C 能覆盖 >96% 的叶子交互。

  工程创新：

  1. Phase 2 A+C 合并：原始实现先收集所有受影响叶子，再分类处理。我们将 Case A
  和 Case C 的 delta 计算和树修改合并在一次遍历中完成，避免重复遍历。
  2. 整数算术：用 long long 替代 double 进行 support
  计数，避免浮点精度累积误差。
  3. robin_hood hash set 交集（Phase 1）：用 intersect_dense_sets
  对两个顶点的叶子邻接集取交集，自动选择较小集合做 probe。

  R≥3 (General r-Clique Nucleus Decomposition)

  创新 4：不可变树 + Case A/C 快速路径提取（CPI-ST for r≥3）

  理论创新：

  r≥3 的核心困难是：删除一个 r-clique 后，受影响的叶子中 r-clique
  的角色更复杂。原始 CPI 对所有受影响叶子都运行完整的 BK
  重新枚举。我们的创新是分类处理：

  - LeafDeath（类似 Case A）：删除的 r-clique 包含某个 keep
  顶点，叶子直接死亡。delta = 全部贡献（nCr 公式），不需要 BK。
  - BK（类似 Case B）：需要 BK 枚举新子叶子。

  关键发现：LeafDeath 占大多数（com-youtube r=3 s=4：LeafDeath=126,992 vs
  BK=1,680,596；但 LeafDeath 处理代价极低，BK 才是瓶颈）。

  创新 5：ST_V4 — Leaf-Clique Reverse Index

  理论创新：

  原始 r≥3 peeling 中，定位"删除的 r-clique 参与了哪些叶子"需要对每个叶子做 hash
   lookup（Support hash map 查找）。我们建立Leaf-Clique Reverse Index：从
  (r-clique) → list of containing leaves 的反向索引，将 O(|Support|) 的 hash
  查找替换为 O(1) 数组查找。

  创新 6：ST_V11 — 批量 bucket move + 紧凑 clique-leaf ID

  工程创新：

  1. Deferred batch bucket move：V4 在每个 delta 更新后立即做 bucket move，V11
  延迟到一轮结束统一处理，避免同一个 r-clique 在一轮内被 move 多次。
  2. Compact clique-leaf ID 映射：减小 reverse index 的内存占用。
  3. BK 中跳过已死叶子：在 BK 枚举子叶子时检查 leafAlive 标志，提前剪枝。

  ---
  跨 R 值的统一理论框架

  我们的全部创新可归纳为一个统一的思想：

  ▎ 在 CPI 框架中，peeling 的代价主要来自"树修改 + 受影响 r-clique 的 support 
  重新计算"。通过利用 SDCT 的 keep/pivot 结构性质，将大多数情况（Case A / Case C
   / LeafDeath）转化为 O(1) 的 nCr 查表 delta 计算，完全避免树修改和 BK 
  重新枚举。

  对于 r=1，进一步发现：树本身完全不需要物化（Tree-Free peeling），所有信息可在
  SDCT 构建时通过回调收集。
