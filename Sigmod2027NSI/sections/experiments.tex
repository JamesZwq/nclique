In this section, we evaluate the builder against the state of the art, and the index against the only baseline that answers the same queries.

\stitle{Hardware.}
All experiments run on a server with two Intel Xeon Gold 6342 processors and $503$\,GB of memory, on a single thread\footnote{Code will be released upon publication.}.
%
All algorithms are implemented in C++ and compiled with \textsf{-O3}.

\stitle{Algorithms.}
\cnd{} is the published state of the art \cite{NuclearCD}, run from its authors' implementation one cell at a time.
%
\buildalg{} is our plane builder (Algorithm~\ref{alg:build}); \queryalg{} is the index query (Algorithm~\ref{alg:query}).
%
The query baseline is the \emph{archive}: one sorted record per scored clique holding its values across the row, probed by binary search.
%
Every archive choice favors the archive: four-byte keys and values, rows counted at their exact number, and a workload that always hits.

\stitle{Datasets.}
Table~\ref{tab:datasets} lists the eight graphs: two web crawls, a collaboration network, a co-purchase network, and four finite-element meshes \cite{nr,Stanford}.
% TODO(dataset-cites): verify the exact source keys for each graph before submission.
The indexed plane is $r\in[3,5]$, $s\le8$ throughout; the grid experiments use the nine cells $s\le r+3$ of that plane.

\stitle{Metrics.}
Time is end-to-end and memory is the peak of the process, both of a single run on an idle machine.
%
\cnd{} receives a $1{,}800$-second budget and a $300$\,GB cap per cell.
%
A red $\times$ marks a cell over the budget, and a red $-$ marks a memory kill.
%
\buildalg{} computes a whole row per sweep, so a cell is charged its marginal time and the row's peak memory.
%
Times below the harness resolution of $0.01$ seconds are drawn at that resolution.

\expsection{Build time against the state of the art}
Figure~\ref{fig:gridtime} shows build time per grid cell on all eight graphs.
%
The y-axis is time in seconds on a log scale, and the x-axis lists the cells of each row.
%
\cnd{} completes $42$ of the $72$ cells; \buildalg{} completes all $72$.
%
It is faster on every one of the $42$.
%
The closest cell is WG at $(3,4)$ with $1.4\times$; the widest is DB at $(5,8)$ with $5{,}806\times$.
%
The gap widens along both parameters, exactly as the certificates predict.
%
Within a row, absorption turns later cells into arithmetic: on DB, $43.31$ seconds against $0.08$ at $(4,6)$.
%
Across rows, the diagonal starts each boundary warm.
%
On WI, \cnd{} finishes none of the nine cells, while our whole rows take $0.81$, $1.60$, and $3.18$ seconds.
%
On a single matched cell computed standalone, WI at $(3,4)$, \cnd{} needs $5{,}581$ seconds and $101$\,GB against our $7.5$ seconds and $0.45$\,GB.
%
That is $742\times$ in time and $226\times$ in memory.

\expsection{Build memory against the state of the art}
Figure~\ref{fig:gridmem} shows peak memory for the same cells.
%
\cnd's memory follows its scored-clique count and crosses $93$\,GB already on the one-million-edge DB at row $5$.
%
Two mesh cells and one WI cell die at the $300$\,GB cap.
%
Our peak follows the pattern count instead and stays between $36$\,MB and $57$\,GB across all $72$ cells.
%
The one graph where \cnd{} is leaner at $r=3$, WG, is the graph with the weakest quotient of the eight; its rows still win on time.

\expsection{Query latency against the archive}

%
Warm queries repeat over a resident working set; cold queries follow a cache eviction.
%
\queryalg{} answers in $74$ to $433$ nanoseconds warm, and it wins $20$ of the $22$ comparisons the archive can enter, by up to $12.7\times$.
%
On WI at $r\ge4$ the archive cannot be built, so the index is the only structure that answers at all.

The archive wins only on AZ at $r\ge4$: its $22$\,MB fit in cache, and a graph whose archive fits in cache does not need an index.

\expsection{The certificates, ablated}
Table~\ref{tab:ablation} disables each transfer theorem in turn and rebuilds the plane.
%
Without absorption, every cell above a boundary is peeled in full: NS slows by $22.6\times$, and PK3 exceeds a $5{,}400$-second budget against its $204$-second default.
%
Without the diagonal, every boundary is peeled cold: $2.4\times$ on NS and $3.0\times$ on PK3, with memory more than doubling.
%
The completed ablations return the same core-number distribution as the default build.

\expsection{Applicability, decided in advance}
The build test of Section~\ref{sec:index} was computed for every candidate graph before any build.
%
It accepted all eight graphs of Table~\ref{tab:datasets}, and it rejected the social networks: \pokec{} at a ratio of $1.001$ and \textsf{email-Eu-core} at $1.002$.
%
In those graphs the vertices are pairwise distinguishable, so the quotient is the graph itself.
%
The rejections cost the front end only, and no index was built to learn them.
