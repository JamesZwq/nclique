贯穿全文的例子:6 个顶点的小图,$(r,s)=(2,3)$(算「每条边在多少个三角形里」,再按这个剥皮)

第 4 步计数:用 region 容斥的纯二项式算 support(不建任何 pivot 树)

包含某条边的三角形 = 这条边再扩 1 个点($s-r=1$),扩的点必须落在 Host 的 region 里。于是 support = Host 这些 region 的"扩展点集合"的并集计数,用容斥:

$$\mathrm{sup}(\tau)=\sum_{\varnothing\neq A\subseteq \mathrm{Host}(\tau)}(-1)^{|A|+1}\binom{\,|\cap A|-r\,}{\,s-r\,}$$

拿最有意思的 CC(边 c–d,Host = {R₁, R₂})算到底:

sup(CC)  =  [R₁] $\binom{|R_1|-2}{1}$  +  [R₂] $\binom{|R_2|-2}{1}$  −  [R₁∩R₂] $\binom{|\{c,d\}|-2}{1}$
    =  $\binom{4-2}{1}$ + $\binom{4-2}{1}$ − $\binom{2-2}{1}$  =  2 + 2 − 0  =  4

验证:包含 c–d 的三角形正好 4 个 —— {c,d,a}、{c,d,b}、{c,d,e}、{c,d,f}。✓ 其它边 Host 只有一个 region,sup = $\binom{4-2}{1}=2$。

怎么读(诚实版)

  • 时间优势 = 稀疏图 + 中高 (r,s)。 那里 CND 的团枚举爆炸,我们 size-free,最高 211×,或 CND 直接超时/几十 GB。
  • 内存优势 ≈ 全局。 连两边都超时的 web-Stanford(5,7),SCT 也只 103M,CND 要 43 GB —— class 级结构内存几乎平的。
  • CND 反赢:低 (r,s)(3,4)/(4,5) + 稠密图。 CND 在那里本就亚秒级,我们剥皮的 overhead 还没追上 —— 这是当前在攻的硬骨头。

总结

顺着这个例子:原图 → region → class → pattern/host → 容斥算 support → class 级 SCT 剥皮。 全程把"顶点上几十万个团"压成"几个 class 上的 pattern"。计数是纯二项式(不建顶点 CPI), 剥皮在 class 级 SCT 上。结果:内存优势几乎全局,时间在稀疏图 + 中高 (r,s) 上大幅领先 CND; 还没拿下的是稠密 / 低 RS。
