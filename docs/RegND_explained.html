RegND:在区域 / 类商上做 (r,s)-Nucleus 分解

不构建顶点级 CPI · 用 class 级的 Succinct Clique Tree · 与 NuclearCD (CND) 的对比

一句话:我们把"逐个 r-clique、在顶点上做"的核分解,搬到一张压缩过的商图上做—— 节点不是顶点,而是可互换顶点的等价类。计数用纯二项式闭式(不建任何 pivot 树), 剥皮用一棵class 级的 Succinct Clique Tree。结果:在高 $(r,s)$ 和稀疏图上, 时间和内存都大幅领先 CND;内存优势几乎是全局的。

1. 问题:(r,s)-Nucleus 分解

给定无向图,固定两个整数 $r < s$。对每个 r-clique(r 个两两相连的点),它的 support 定义为"包含它的 s-clique 个数"。把所有 r-clique 按 support 从小到大剥皮(peel): 每次拿掉 support 最小的那个,记下它的 core number,并把因此死掉的 s-clique 从其它 r-clique 的 support 里扣除,直到全部剥完。输出 = 每个 r-clique 的 core number 分布。

例:$(r,s)=(3,4)$ 就是"三角形在四团里的核分解";$(4,5)$ 是"四团在五团里的核分解"。

2. Baseline:CND(NuclearCD)顶点级

经典做法在顶点粒度、逐个 r-clique 上算:枚举出所有 r-clique 和 s-clique,逐个维护 support、逐个剥。 正确、而且在低 $(r,s)$ 时很快(团很少、枚举便宜)。但它有一个致命点:

CND 必须把所有 r-clique / s-clique 物化出来。 当 $(r,s)$ 升高,团的数量组合爆炸, 时间和内存随之爆炸。实测 ca-GrQc 在 $(6,8)$ 时 CND 已占用 2 GB,$(7,10)$ 时 近 9 GB 且跑不完;com-dblp、web-Stanford 在中等 $(r,s)$ 就要几十 GB。

3. RegND 的核心:区域 / 类商(quotient)

用三个对象把"巨量但等价"的东西压成"少量":

概念定义作用
Region大小 $\ge s$ 的极大团(MCE 枚举得到)任何 s-clique 一定整个落在某个 region 内
Classregion-成员身份完全相同的一组顶点(互相可交换)把 $n$ 个顶点压成 $n_C$ 个 class(通常小一两个数量级)
Pattern / Tuple一个 r-clique orbit 的 class-重数签名(每类取几个点)把巨量 r-clique 压成少量 pattern —— size-free 的关键

还有一个关键量 Host($\tau$) = 包含某 r-clique 的所有 region 的集合。

决定性事实(整个算法的地基): 一个 r-clique 的 s-support 只取决于它的 Host(在哪些 region 里), 跟它具体是哪几个点无关。所以同一个 pattern 的所有 r-clique support 相同 —— 只需算一次。

实测压缩比:ca-GrQc 5242 个顶点 → 仅 199 个 class;1,680,912 个 4-clique → 仅 22,542 个 pattern(com-dblp 同理 317K 顶点 → 69K class)。

4. 计数那一半:region 容斥,纯二项式闭式,不建任何 pivot 树 class 级

一个包含该 r-clique 的 s-clique,要再扩 $(s-r)$ 个点,这些点必须落在 Host 的 region 里。于是 support 就是这些 region "扩展点集合"的并集计数 —— 用 region 容斥(region-IE):

$$\mathrm{sup}(\tau)=\sum_{\varnothing\neq A\subseteq \mathrm{Host}(\tau)}(-1)^{|A|+1}\binom{\,|\cap A|-r\,}{\,s-r\,}$$

其中 $|\cap A|$ 是 $A$ 里这些 region 的交集大小。全程在 class 粒度(region 的交 = 一小撮 class)。 这正是region_native.cpp 头注释写的: "compute the s-clique support ... with NO CPI/SDCT pivot index"。三个优化(只枚举多-region 的 class、 深度栈增量维护 Host、按 Host 哈希 memoize)让它真正 size-free:com-dblp $(7,8)$ 从 75.78s → 0.89s。

所以计数完全是组合数 + 容斥,没有 DP、没有顶点级 pivot 树。这是 RegND 最干净的一半。

5. 剥皮那一半:class 级的 Succinct Clique Tree(ClassSCT) class 级

剥皮要在"witness 不断死掉"中维护每个 pattern 的 live support。RegND 不建顶点级 CPI,而是:

  1. 建商图:节点 = class,两个 class 间连边 ⟺ 它们在某个 region 里共现(即完全互相邻接)。
  2. 对商图建一棵 class-加权的 s-clique SCT(只建一次)。SCT 的叶子是不相交的 CCPath:每个加权 s-clique witness 恰好落在一个叶子里。
  3. 于是 support(pattern) = 它所在叶子的 support_count 之和 —— 纯求和,没有容斥(叶子不相交,没东西要减)。
  4. 剥皮 = pattern 粒度的桶队列;剥掉 P 时把它的阈值塞进所在叶子的 forbidden 集合,受影响的 pattern = 与 P 共享叶子的那些。

代码就是 region_native_sct_peel.cpp,include 的是 ClassSCT.h / ClassSCTScalable.h, 没有 include 顶点级的 SDCT_Fused/SDCT。整条线唯一的顶点级操作只有 MCE(找 region = 极大团),之后全在 class 商上。

6. 为什么"更小、更快"?class 级 vs 顶点级

RegND:结构规模 = O(#class)

SCT 的节点是 class,几百个;叶子几百个。几乎不随 $(r,s)$ 变化 —— 团多不多,商图就那么大。

ca-GrQc(4,5):nC=199, base-leaves=285。

CND:结构规模 = O(#r-clique)

要物化所有 r-clique / s-clique,数量随 $(r,s)$ 组合爆炸 → 内存随 RS 爆到 GB 级。

ca-GrQc:251K 个 4-clique;高 RS 时几百万。

所以 RegND 的内存几乎是平的(只跟 class 数走),而 CND 的内存随 RS 起飞。这是下面实验里 SCT_MB 一直 ~25M、CND_MB 涨到几十 GB 的根本原因。

怎么读这张表(诚实版)

  • 时间优势 = 稀疏图 + 中高 $(r,s)$。 ca-GrQc(≥5,7)、dblp-core30(几乎全程)上 SCT 把 CND 打爆(最高 211×,以及 CND 直接超时/几十 GB)。这正是 CND 的 r-clique 枚举爆炸、而我们 size-free 的地方。
  • 内存优势 ≈ 全局。 即使在 SCT 也超时的格子(web-Stanford(5,7)),SCT 也只用 103M 而 CND 要 43 GB。class 级结构的内存几乎平的。
  • CND 反而赢的地方:低 $(r,s)$(3,4)/(4,5) + 稠密图。 ca-CondMat、ca-HepPh、以及大图 com-dblp/web-Stanford 的低 RS —— 那里 CND 本来就亚秒级,我们的剥皮 overhead 还追不上。ca-HepPh 太稠密,SCT 在 (3,4) 都会超时。

8. 当前状态与瓶颈(给后续优化看的)

计数一半是干净、可扩展的胜利;瓶颈在剥皮。在稠密 / 低 RS 的格子上,剥皮里"找受影响 pattern"的枚举有 ~40× 空枚举(每个 leaf-peel 生成 ~57 个候选,只有 ~4 个真受影响),根因是 controlled_split 把叶子炸成几千条 path(dead-tracking 的代价)。已落地的 bit-identical 优化(in-place 重建、sum-guard、 forbidden early-out)让稠密 (4,5) 快了 ~36%,但还差几倍。理论上界很清楚:真受影响集合满足闭式 $E(P\!\to\!Q)=\sum_c\max(0,q_c-p_c)\le T-r$,对 $(4,5)$ 只有 ~4 个,所以"剥皮逼近 fundamental、过 CND"是可达的, 关键是更省的 dead-tracking。

总结

RegND = 把核分解搬到 class 商上做:计数用 region 容斥的纯二项式(不建顶点 CPI),剥皮用 class 级 SCT。 因为结构规模只跟 class 数走、不随 $(r,s)$ 爆炸,所以内存优势几乎全局,时间在稀疏图 + 中高 $(r,s)$ 上大幅领先 (CND 在那里因 r-clique 枚举爆炸而超时/吃几十 GB)。尚未拿下的是稠密图 / 低 RS —— CND 在那里本就极快, 是剥皮 dead-tracking 还需突破的硬骨头。
