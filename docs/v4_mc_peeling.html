The issue: MC death condition "C(|M|-r,s-r) ≤ minCore" is too aggressive. M1 and M2 both have C(2,1)=2, but τ3's support is 4 (not 2). M should only die when ALL its unique tuples are peeled, not when C(|M|) ≤ minCore.

Corrected MC Death Condition

!
MC dies when ALL its tuples with only this MC left are peeled

Track per-tuple: aliveMCcount[τ] = number of alive MCs containing τ.

When tuple τ is peeled:

  • For each MC M containing τ: if τ was the last "reason" keeping M alive → M dies
  • M dies when: ALL tuples with aliveMCcount == 1 and that "1" is M have been peeled

In the example:

Round 1 (core=2): peel τ1,τ2,τ4,τ5 (support=2)
• τ1 only in M1 ⇒ peel, M1 loses one unique tuple
• τ2 only in M1 ⇒ peel, M1 loses another
• τ4 only in M2 ⇒ peel
• τ5 only in M2 ⇒ peel

Now: M1's unique tuples (τ1,τ2) are ALL peeled ⇒ M1 DIES
M2's unique tuples (τ4,τ5) are ALL peeled ⇒ M2 DIES

Update τ3: was in {M1,M2}, both dead ⇒ support = 0 ⇒ core = max(2, 0) = 2

!!
Root cause: peeling order

The standard peeling pops the min-support tuple. τ3 has support=4. It should NOT be peeled until level 4.

τ1,τ2,τ4,τ5 all have support=2. They peel at core=2.

When they peel: what happens to τ3's support?

Before: support(τ3) = 4 (from M1 and M2)

Peeling τ1 = (A,A,B): s-cliques killed = those in M1 containing τ1 AND τ3
= {S ⊆ M1: (A,A,B) feasible, (B,B,B) feasible} = {S: ≥2A + ≥3B, |S|=4}
= need 2+3=5 vertices but |M1|=5 and s=4 ⇒ S must have ≥2 from A(2 avail) AND ≥3 from B(3 avail) in 4 slots. 2+3=5>4. Impossible!
Δ = 0. τ3 is NOT affected by peeling τ1.
Similarly τ2=(A,B,B): need ≥1A + ≥3B (for τ3) in same S. 1+3=4=s. Possible!
S = {some A, all 3 B} = {0,2,3,4} or {1,2,3,4}. Two s-cliques.
But these also contain τ2's pattern (1A+2B) ⇒ Δ(τ3) from peeling τ2 = 2.

After peeling τ2: support(τ3) = 4 - 2 = 2.
Similarly τ4=(B,B,C): need ≥3B + ≥1C in S ⊆ M2. 3+1=4=s.
S = {all 3 B, 1 C} = {2,3,4,5} or {2,3,4,6}. Two s-cliques.
Δ(τ3) from peeling τ4 = 2.

After: support(τ3) = 2 - 2 = 0.

So τ3 ends up at support=0, core = max(2, 0) = 2.

But the correct core for τ3 = {2,3,4} is 4 (in 4 s-cliques initially, standard peeling gives core=4).

The MC death condition "C(|M|-r,s-r) ≤ minCore" is WRONG. The current implementation passes correctness checks because the MC death condition happens to align with actual peeling on dblp-core30. But the algorithm needs refinement for general correctness.

Correct Algorithm (Refined)

☆
The key: don't use MC death. Just compute Δ directly.

When peeling τ at level k, for each surviving τ':

Δ(τ', τ) = ΣM ∈ MCs(τ) ∩ MCs(τ')
   ΣB ⊆ aliveMCs(τ') \ {M} (-1)|B| · C(|M ∩ (∩B)| - r, s - r)

This is the number of alive s-cliques containing BOTH τ and τ'.

Each term = one C(n,k). Number of terms = O(2d) where d = |MCs(τ')| ≤ 5 typically.

No MC death tracking needed. Just recompute support from alive MCs after each peeling.

An MC is "alive" simply if it hasn't been fully accounted for by peeled tuples.
