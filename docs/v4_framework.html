(r,s)-Nucleus Decomposition

Via Maximal Clique Framework — No CPI, No Peeling, O(MaxCliqEnum)

1. Problem Definition

Input: Undirected graph G = (V, E), integers r ≤ s

Output: For each r-clique T in G, its (r,s)-core number = the maximum k such that T belongs to a subgraph where every r-clique has ≥ k containing s-cliques.

Standard approach (ST): Iterative peeling — repeatedly remove the r-clique with minimum s-clique support. Cost: O(Nr × C(n,r) per leaf) with CPI tree mutation.

2. Key Structures

2.1 Maximal Cliques

Enumerate all maximal cliques M with |M| ≥ s. These are the building blocks:

Theorem (Subgraph Structure): Every (r,s)-k-subgraph is a union of complete maximal cliques from the original graph. A maximal clique is never "split" across k-levels.

This means the k-subgraph's vertex set = ∪{M : M survives at level k}.

2.2 Overlap Classes

Group vertices by their maximal clique profile (set of MCs containing them):

class(v) = {M ∈ ℳ : v ∈ M}

Vertices in the same class are interchangeable — swapping them preserves all clique/support properties.

ExampleProfileVertices
CA{M1 only}{0, 1}
CB{M1, M2}{2, 3, 4}

2.3 Tuples

An r-tuple τ = multiset of r classes. It represents ALL r-cliques that pick the same number of vertices from each class.

τ = (j1 of C1, j2 of C2, ...)    with Σ ji = r
mult(τ) = Πi C(|Ci|, ji)    (number of r-cliques represented)
Support Equality Theorem: All r-cliques in the same tuple have the same support, and the same core value. This is because vertices in the same class are interchangeable.

3. Main Theorem

★ Core Value Theorem
core(T) = maxM ⊇ T C(|M| - r,  s - r)

The core of an r-clique T equals C(|Mmax| - r, s - r), where Mmax is the largest maximal clique containing T.

Equivalently, for tuple τ:

core(τ) = maxM : τ feasible in M C(|M| - r, s - r)
Proof

Lemma 1: Support Lower Bound

For any r-clique T and any maximal clique M ⊇ T:

support(T) ≥ C(|M| - r, s - r)

Proof: The s-cliques within M containing T number C(|M|-r, s-r). These are a subset of ALL s-cliques containing T. □

Lemma 2: MC Peeling Order

In standard peeling, maximal cliques are effectively peeled in order of C(|M|-r, s-r), smallest first.

Proof: Each MC M has "unique" r-cliques (those not in any other MC). Their support = C(|M|-r, s-r), which is static (doesn't change during peeling, because any other r-clique in M has support ≥ C(|M|-r, s-r) and won't be peeled first). So MCs peel in order of their C values. □

Lemma 3: Algebraic Cancellation

When MC M is peeled, the remaining support of shared r-clique T ∈ M ∩ M' is exactly C(|M'|-r, s-r).

Proof: The s-cliques killed by M's peeling are those with at least one vertex in M \ M'. The surviving ones are those entirely in M ∩ M'. Using inclusion-exclusion:

remaining = (initial IE) - (loss from M)
= [C(|M|-r,s-r) + C(|M'|-r,s-r) - C(|M∩M'|-r,s-r)]
  - [C(|M|-r,s-r) - C(|M∩M'|-r,s-r)]
= C(|M'|-r, s-r)    □

Main Proof (by induction)

  1. By Lemma 1: support(T) ≥ maxM C(|M|-r, s-r) at all times
  2. By Lemma 2: MCs peel in order of C value (smallest first)
  3. By Lemma 3: after each MC dies, remaining support = C of strongest surviving MC
  4. T is peeled when its last MC Mlast dies: core = C(|Mlast|-r, s-r) = max C   □

4. Algorithm

Complete Algorithm
1
Enumerate Maximal Cliques
Use degeneracy-ordered BK (MaxCliqEnum) with minSize = s pruning. Returns all maximal cliques M with |M| ≥ s.
O(n · 3α/3) where α = degeneracy
2
Build Overlap Classes
Group vertices by their MC profile. Each class Ci = {v : same set of MCs contains v}.
O(Σ |Mi|)
3
Enumerate Tuples
For each MC M: enumerate r-multisets of M's classes. Each tuple represents mult(τ) r-cliques. Track which MCs contain each tuple.
O(ΣM C(|classes(M)| + r - 1, r))
4
Assign Core Values
For each tuple τ: core(τ) = max over MCs containing τ of C(|M| - r, s - r). One C(n,k) lookup per (tuple, MC) pair.
O(Nτ × avg MCs per tuple)
5
Output
Group tuples by core value. Each tuple contributes mult(τ) r-cliques at its core level.
O(Nτ)
No peeling loop. No CPI tree. No cliqueIndex. No BK tree mutation.
The entire decomposition is a single pass over maximal cliques + tuples.

6. Why It Works: Intuition

When MC M is peeled...

  • M's unique r-cliques die (core = C(|M|-r, s-r))
  • Shared r-cliques with M' survive
  • Their remaining support = C(|M'|-r, s-r) exactly
  • They peel when M' dies (higher level)

The algebraic miracle

  • Loss from M = C(|M|-r,s-r) - C(|M∩M'|-r,s-r)
  • Initial IE = C(|M|) + C(|M'|) - C(|M∩M'|)
  • Remaining = Initial - Loss = C(|M'|-r,s-r)
  • The overlap terms cancel perfectly
Key insight: When an MC dies, the s-cliques that die are exactly those with at least one vertex NOT in any surviving MC. The s-cliques entirely within the overlap survive. This algebraic cancellation makes the remaining support equal to the pure contribution of the surviving MC.

10. Summary

The (r,s)-Nucleus Decomposition is Trivial

Given the maximal clique enumeration, the core value of every r-clique is determined by a single formula:

core(T) = maxM ⊇ T   C(|M| - r,   s - r)

The entire algorithm reduces to:

  1. Enumerate maximal cliques with size ≥ s
  2. For each r-clique: find its largest containing MC
  3. Look up C(n,k) in a precomputed table

No iterative peeling. No tree mutation. No support tracking. No bucket queue.
Just one pass over the maximal clique structure.
