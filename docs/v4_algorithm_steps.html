Key Insight

Each support update should be ONE C(n,k) per (tuple, leaf), not C(n,r) enumeration.
But tracking alive s-cliques across multiple peeling steps requires either:

Inclusion-Exclusion
O(2p) per (tuple, leaf)
p = dead tuples on leaf
Exponential when p large
BK Tree Mutation
Physically remove dead s-cliques
Avoids IE but needs C(n,r) enum
Per-r-clique cost
This is #P-hard (counting alive s-cliques)
Hybrid Solution
p < 8: Inclusion-Exclusion (fast, exact, O(256 × r))
p ≥ 8: BK fallback (exact, O(C(n,r)) but rare)
