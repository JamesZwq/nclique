This section answers the third difficulty of Section~\ref{sec:intro}: how to build the trees of every size from one computation.
%
% 2026-09-22 compaction: opener in four sentences.
The values of one size come from a \textit{peel}.
%
% 2026-09-22 cold read 2: the clique count is the current one; a replay is not a peel; the traversal rule and the node numbering of Step 3 match the build (items merged by smallest rank; nodes renumbered in the traversal order); the reason for the top of a changed component; the trie bound.
% 2026-09-23 cold read (Section 7): the verb of the peel sentence; "skips the known values"; "that size"/"that tree"; the peel computes; the proof of (b); t defined; the floor of v; tail start glossed and the arithmetic written; "either"; the proof's steps; the omission sentence; sizes are not settled; the example's size-2 values; the cost's three pairs.
The peel removes the vertices one at a time, each time one with the smallest \textit{clique count}, the number of $s$-cliques through it among the vertices not yet removed.
%
The largest count seen at a removal so far is the core value of the removed vertex.
%
The index is built from one clique tree, giving the clique counts of every size, and one peel per size that skips the vertices whose values are already known.
%
The tree of each size is built as the values of that size arrive, and the chains are split with that tree (Figure~\ref{fig:pipeline}).

\stitle{Core values from one clique tree.}
The clique counts come from a pivoting clique tree~\cite{Pivoter}, built once and shared by every size.
%
% 2026-09-22 compaction: the clique tree, the replay and the forward counts in eight sentences.
Each root-to-leaf path carries a mandatory set $H$ and an optional set $Q$ whose union is a clique.
%
The path represents the cliques $H\cup Z$ for every subset $Z$ of $Q$ with $s-|H|$ vertices.
%
Every $s$-clique of the graph is represented by exactly one path.
%
The number of $s$-cliques of a vertex $v$ inside a vertex set $W$ is therefore a sum over the paths through $v$ whose mandatory set lies in $W$.
%
A path contributes $\binom{|Q\cap W|}{s-|H|}$ when $v$ is mandatory on it, and $\binom{|Q\cap W|-1}{s-|H|-1}$ when $v$ is optional, since then $Z$ must contain $v$.
%
% 2026-09-23 proof check (codex, Fable): a removal lowers a count by the cliques containing both vertices, not all cliques of the path through the removed one.
When the peel removes a vertex $u$, the count of every other vertex $v$ on a path through $u$ decreases by the number of cliques of the path that contain both.
%
With $r$ of the two vertices optional on the path, this number is $\binomc{|Q\cap W|-r}{s-|H|-r}$.

\stitle{Settled vertices.}
The peel of a size reads every path of that size, but Theorem~\ref{thm:tail} already gives many of the values that the peel computes.
%
% 2026-09-23 proof check: s >= 3 and t >= s-2 for the bound; the integer bound named; the value's reason; "after" is s > sigma(v).
For $s\ge3$, the value at size $s-1$ bounds the value from above, by the proof of Theorem~\ref{thm:tail}(b) applied to the sizes $s-1$ and $s$: $\core{s}{v}\le\binomc{t}{s-1}$, where $t\ge s-2$ is the real number with $\binomc{t}{s-2}=\core{s-1}{v}$.
%
The construction uses the theorem in its original form~\cite{kruskal1963,katona1968}, whose bound is an integer no larger than this one.
%
A vertex $v$ with $\omg{v}\ge s$ is \textit{settled} at size $s$ when this integer bound equals the floor of $v$, $\binomc{\omg{v}-1}{s-1}$.
%
Its value is then the floor, since it lies between the floor (Theorem~\ref{thm:tail}(a)) and the bound.
%
At every size $s$ after its tail start $\sig{v}$, a vertex has the value $\binomc{\omg{v}-1}{s-2}$ at size $s-1$, so $t=\omg{v}-1$, the bound is the floor, and the vertex is settled.
%
% 2026-09-23 compaction: the settled share (93 percent on com-dblp) is left to Exp-1's statement of where settling pays.
In the peel below, the \textit{key} of a settled vertex is its value, and the key of any other, \textit{unsettled}, vertex is the smaller of its clique count and its bound.
%
At size $2$, the first size peeled, there is no bound: no vertex is settled, and every key is a clique count.
\begin{theorem}[peel with settled vertices]\label{thm:settled}
Let every vertex $v$ with $\omg{v}\ge s$ be either settled, with key $\core{s}{v}$, or unsettled, with key the smaller of its clique count and a bound of at least $\core{s}{v}$.
%
Remove these vertices one at a time, each time one of smallest key, and give each the largest key seen at a removal so far.
%
Every such vertex receives its core value $\core{s}{v}$.
\end{theorem}
\begin{proof}
% 2026-09-23 proof check (codex exhaustive to 6 vertices with every bound, settled set and tie order; Fable 42,408 random peels): true; the maximality step, the empty case and the settled vertex's membership in D_k are now written.
Fix a level $k\ge1$, and let $D_k$ be the vertices of value at least $k$, the union of the cores of size $s$ at level $k$.
%
Every vertex of $D_k$ lies in at least $k$ $s$-cliques inside $D_k$.
%
Conversely, a set whose every vertex lies in $k$ or more $s$-cliques inside it lies inside $D_k$: each part connected through these cliques has both properties of Definition~\ref{def:nucleus} at level $k$.
%
Until a vertex of $D_k$ is removed, every vertex of $D_k$ has key at least $k$, since its value, or else both its bound and its count, are at least $k$.
%
The first vertex of $D_k$ to be removed thus has key at least $k$, and a removal with key at least $k$ occurs whenever $D_k$ is not empty.
%
Just before the first removal with key at least $k$, the remaining vertices, call them $R$, include all of $D_k$.
%
Every vertex of $R$ has key at least $k$, and an unsettled one lies in at least $k$ $s$-cliques inside $R$ because its count is at least its key.
%
A settled one has value at least $k$ and lies in $D_k$, where it lies in at least $k$ $s$-cliques, all inside $R$.
%
By the converse, $R=D_k$, so exactly the vertices of $D_k$ receive a value of at least $k$, and every vertex receives $\core{s}{v}$.
\end{proof}
% 2026-09-23 proof check: why the settled vertices on no followed path can be left out; why a size without unsettled vertices ends the peels.
The peel never reads the count of a settled vertex, and a removal lowers the counts of the vertices that share a path with the removed vertex.
%
The peel of size $s$ thus follows the paths through unsettled vertices.
%
Removing a settled vertex that lies on none of these paths changes no key and happens at the smallest key, so leaving the vertex out changes no value.
%
Once a size has no unsettled vertex, every value there is a floor, and every vertex is settled at every later size.
\begin{example}\label{ex:settled}
% trace 2026-09-23: tools/example_check.py (settled and unsettled per size, 12 triangles through the unsettled vertices, all removed at level 3).
Consider Figure~\ref{fig:example} at size $3$.
%
The vertices $a_1,\dots,a_5$ and $b_1,b_2,b_3$ have their floors $4$ and $3$ as values at size $2$ (Example~\ref{ex:tail}), which makes their bounds $\binom{4}{2}=6$ and $\binom{3}{2}=3$ at size $3$ their floors, and they are settled.
%
The value of $x$ and of the six vertices $u_1,\dots,w_3$ at size $2$ is $4$, which gives the bound $\binom{4}{2}=6$, above their floors $3$ and $1$, and these seven vertices are unsettled.
%
The peel counts triangles only for them: $x$ lies in $12$, nine through $U$ and $W$ and three inside $B$, and each of the other six lies in $3$.
%
% 2026-09-23 proof check: the order among equal keys is free; the sentences hold for every order.
The smallest keys are $3$, of $u_1,\dots,w_3$ and of the settled $b_1,b_2,b_3$, and these nine vertices leave at level $3$.
%
Once $u_1,\dots,w_3$ are gone, $x$ lies in at most the three triangles of $B$, fewer if some $b_i$ left first, and it leaves at level $3$ as well.
%
No triangle joins $a_1,\dots,a_5$ to an unsettled vertex, and the peel never visits them.
%
At size $4$, $x$ is settled, since its value $3$ at size $3$ equals its floor $\binom{3}{2}$ there, and the $a_i$ and $b_i$ stay settled.
\end{example}

\begin{algorithm}[t]
\caption{\build: the chain index from one clique tree.}\label{alg:build}
\SetAlgoLined\DontPrintSemicolon
\KwIn{a graph $G$.}
\KwOut{\chainidx: the map, the chain records, one tree with a run array per size.}
$T\leftarrow$ the clique tree of $G$; $\omg{\cdot}\leftarrow$ the clique numbers read from $T$\;\label{ln:b-tree}
$\mathrm{node}[v]\leftarrow$ the root of an empty trie, for every vertex $v$\;\label{ln:b-trie}
\For{$s\leftarrow2,3,\dots$ \KwSty{while} some vertex lies in an $s$-clique}{\label{ln:b-sizes}
  \tcp{Step 1: the values of size $s$}
  $\core{s}{v}\leftarrow\binomc{\omg{v}-1}{s-1}$, for every vertex $v$ settled at size $s$\;\label{ln:b-settle}
  $\core{s}{v}\leftarrow$ its value in the peel of Theorem~\ref{thm:settled} on the paths of $T$ through unsettled vertices, for every unsettled $v$\;\label{ln:b-peel}
  \tcp{Step 2: the tree of size $s$ and the chains}
  $\mathrm{active}[v]\leftarrow$ false, for every vertex $v$\;\label{ln:b-reset}
  \ForEach{value $k$ of size $s$, in decreasing order}{\label{ln:b-levels}
    $\mathrm{active}[v]\leftarrow$ true, for every $v$ with $\core{s}{v}=k$\;\label{ln:b-activate}
    join the active vertices of every live path with a newly active vertex into one component\;\label{ln:b-union}
    every component that changed becomes a node of $\Tree{s}$ with top $k$\;\label{ln:b-nodes}
    the nodes that the changed component absorbed become its children\;\label{ln:b-parent}
    $\own{s}{v}\leftarrow$ the component of $v$, for every $v$ with $\core{s}{v}=k$\;\label{ln:b-own}
  }
  $\mathrm{node}[v]\leftarrow$ the child of $\mathrm{node}[v]$ labelled $\own{s}{v}$, created if absent, for every active $v$\;\label{ln:b-refine}
  $\mathrm{value}[\mathrm{node}[v]][s]\leftarrow\core{s}{v}$, for every active $v$\;\label{ln:b-value}
}
\tcp{Step 3: the layout}
rank the chains, the stopped sets of the trie, in its depth-first order; label the vertices\;\label{ln:b-rank}
record the chain starts\;\label{ln:b-bitmap}
\ForEach{size $s$}{\label{ln:b-layout}
  traverse $\Tree{s}$ with children by smallest rank\;\label{ln:b-traverse}
  merge consecutive ranks into runs; record the entry of every node\;\label{ln:b-runs}
}
\lForEach{chain $c$}{store $\omega$, $\sigma$, the residues from $\mathrm{value}[c][\cdot]$, the trajectory}\label{ln:b-values}
\end{algorithm}

\stitle{Algorithm.}
% 2026-09-22 algorithm pass: the float names its three steps, assigns to named arrays (active, node, own node) and calls the peel and the forward counts by name; the walk follows the steps.
Algorithm~\ref{alg:build} has two steps for every size, the values (Step 1) and the tree with the refinement of the chains (Step 2), and one step after the last size, the layout (Step 3).
%
% 2026-09-22 compaction: the walk in eighteen sentences.
A path of the clique tree $T$ is \textit{live} when its mandatory vertices are all active and at least $s$ of its vertices are active.
%
Every $s$-clique of active vertices lies on the one path that represents it, which is then live, and any $s$ active vertices of a live path form an $s$-clique of active vertices.
%
Before the first size, the algorithm builds the clique tree once and reads from it the clique number of every vertex (Line~\ref{ln:b-tree}).
%
The algorithm puts every vertex at the root of the trie that will hold the chains (Line~\ref{ln:b-trie}).
%
\emph{During Step 1}, for every size (Line~\ref{ln:b-sizes}) it gives every settled vertex its floor, based on Theorem~\ref{thm:tail} (Line~\ref{ln:b-settle}).
%
Based on Theorem~\ref{thm:settled}, it peels the unsettled vertices on the paths through them, with the settled vertices of these paths keyed by their values (Line~\ref{ln:b-peel}).
%
\emph{During Step 2}, the algorithm builds the tree of size $s$ from its values.
%
It starts with no vertex active (Line~\ref{ln:b-reset}), goes through the values from the highest down (Line~\ref{ln:b-levels}), and activates the vertices of the current value (Line~\ref{ln:b-activate}).
%
It joins the active vertices of every live path that gained an active vertex into one component (Line~\ref{ln:b-union}).
%
By the two facts about live paths, the components are exactly the sets of active vertices connected through $s$-cliques of active vertices.
%
After each value $k$, the components that changed are the canonical nodes of top $k$ (Line~\ref{ln:b-nodes}).
%
Every active vertex has value at least $k$, and a changed component holds a vertex of value $k$.
%
The nodes they absorbed become their children (Line~\ref{ln:b-parent}).
%
Every vertex activated at that value records its component as its own node (Line~\ref{ln:b-own}).
%
The chains are refined in a prefix trie whose nodes are labelled by own nodes.
%
At size $2$ the vertices are grouped by their own node, and at each later size every group is split by the own node of that size (Line~\ref{ln:b-refine}).
%
A vertex stops at its trie node once the size exceeds its clique number.
%
A chain is the set of vertices that stopped at one trie node, and its trajectory is the path of labels from the root.
%
The value of size $s$ is the same for every vertex that moves to one trie node, and the node records it (Line~\ref{ln:b-value}).
%
The tree of size $s$ is kept as its nodes with their tops and parents, numbered for now in a preorder $\mathrm{pre}_s$, which Section~\ref{sec:order} uses for the keys.
%
\emph{During Step 3}, the algorithm ranks the chains by a depth-first traversal of the trie.
%
The traversal visits the vertices stopped at a node before the node's children, and the children in increasing order of the preorder number $\mathrm{pre}_s$ of their own node.
%
This is the lexicographic key order of Section~\ref{sec:order}, and it gives the chain ranks, the aligned labels (Line~\ref{ln:b-rank}) and the chain starts (Line~\ref{ln:b-bitmap}).
%
For each size the algorithm traverses the tree over chains of Section~\ref{sec:runs} (Line~\ref{ln:b-traverse}).
%
At each node it lists the chains whose own node it is, read from the trajectories, and the subtrees of its children in one sequence by smallest chain rank.
%
It renumbers the nodes in this traversal order.
%
It merges the chain sequence into runs and records every node's entry (Line~\ref{ln:b-runs}).
%
Each chain then receives its clique number $\omega$, its trajectory and its recorded values (Line~\ref{ln:b-values}).
%
The tail start $\sigma$ is the first size at which the chain's value equals the floor, and only the values below $\sigma$, the residues, are stored.

\begin{example}\label{ex:build}
% trace 2026-09-21: tools/example_check.py (nodes, own nodes, chains); LEDGER.md (ranks, runs, entries).  2026-09-22: three sentences.
In Figure~\ref{fig:example} at size $2$, activating the value $4$ joins $A$ into one component and $\{x,u_1,\dots,w_3\}$ into another, the two nodes of top $4$.
%
Activating the value $3$ joins everything into the root of top $3$, and the trie then has three children of the root, holding $\{b_1,b_2,b_3\}$, $\{a_1,\dots,a_5\}$ and $\{x,u_1,\dots,w_3\}$.
%
At size $3$ no group is split.
%
At size $4$ the third group splits: $u_1,\dots,w_3$ stop, since the size exceeds their clique number, and $x$ moves on to the child labelled by the size-$4$ node $B$.
%
The four trie nodes where vertices stopped, the dashed leaves of Figure~\ref{fig:pipeline}, are the chains of Example~\ref{ex:chains}, ranked $0$ to $3$ by the traversal.
%
The layout of size $3$ produces the runs and entries of Figure~\ref{fig:layout}.
\end{example}

\stitle{Cost.}
% 2026-09-23: the shares are measured (Exp-1); the index passes are not "a few percent" (18-85 percent of the build).
% 2026-09-23 compaction: the time shares are measured in Exp-1 and not repeated here.
The refinement adds, for every live path, one union per vertex that becomes active on it, and one trie step per vertex and size.
%
The layout adds one pass per size over the chains.
%
The working space is the clique tree and the graph, plus the values of two consecutive sizes, the trie, and the trees of the sizes with one node per canonical node.
%
The values take space linear in the vertices, the trie in the (chain, size) pairs, and the trees in the canonical nodes.
