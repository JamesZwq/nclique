This section answers the third difficulty of Section~\ref{sec:intro}: how to build the trees of every size from one computation.
%
% 2026-09-22 compaction: opener in four sentences.
The values of one size come from a \textit{peel}.
%
% 2026-09-22 cold read 2: the clique count is the current one; a replay is not a peel; the traversal rule and the node numbering of Step 3 match the build (items merged by smallest rank; nodes renumbered in the traversal order); the reason for the top of a changed component; the trie bound.
% 2026-09-23 cold read (Section 7): the verb of the peel sentence; "skips the known values"; "that size"/"that tree"; the peel computes; the proof of (b); t defined; the floor of v; tail start glossed and the arithmetic written; "either"; the proof's steps; the omission sentence; sizes are not settled; the example's size-2 values; the cost's three pairs.
The peel removes the vertices one at a time, each time one with the smallest \textit{clique count}, the number of $s$-cliques through it among the vertices not yet removed.
%
The largest count seen at a removal so far is the core value of the removed vertex.
%
The index is built from one clique tree, giving the clique counts of every size, and one peel per size that skips the vertices whose values are already known.
%
The tree of each size is built as the values of that size arrive, and the chains are split with that tree (Figure~\ref{fig:pipeline}).

\stitle{Core values from one clique tree.}
The clique counts come from a pivoting clique tree~\cite{Pivoter}, built once and shared by every size.
%
% 2026-09-22 compaction: the clique tree, the replay and the forward counts in eight sentences.
Each root-to-leaf path carries a mandatory set $H$ and an optional set $Q$ whose union is a clique.
%
The path represents the cliques $H\cup Z$ for every subset $Z$ of $Q$ with $s-|H|$ vertices.
%
Every $s$-clique of the graph is represented by exactly one path.
%
The number of $s$-cliques of a vertex $v$ inside a vertex set $W$, written $c_s(v,W)$, is therefore a sum over the paths through $v$ whose mandatory set lies in $W$.
%
A path contributes $\binom{|Q\cap W|}{s-|H|}$ when $v$ is mandatory on it, and $\binom{|Q\cap W|-1}{s-|H|-1}$ when $v$ is optional, since then $Z$ must contain $v$.
%
% 2026-09-23 proof check (codex, Fable): a removal lowers a count by the cliques containing both vertices, not all cliques of the path through the removed one.
When the peel removes a vertex $u$, the count of every other vertex $v$ on a path through $u$ decreases by the number of cliques of the path that contain both.
%
With $r$ of the two vertices optional on the path, this number is $\binomc{|Q\cap W|-r}{s-|H|-r}$.

\stitle{Settled vertices.}
The peel of a size reads every path of that size, but Theorem~\ref{thm:tail} already gives many of the values that the peel computes.
%
% 2026-09-23 simplification (user: elegant paper, engineering stays in the code): settled = past the tail start; the
% unsettled key is the plain clique count.  The code settles with the integer Kruskal-Katona bound and caps counts by it,
% a refinement of this algorithm (it settles a superset and gives the same values).
A vertex $v$ with $\omg{v}\ge s$ is \textit{settled} at size $s$ when $s>\sig{v}$, that is, when its value at size $s-1$ is already its floor.
%
By Theorem~\ref{thm:tail}(b), its value at size $s$ is then the floor $\binomc{\omg{v}-1}{s-1}$.
%
The other vertices, the \textit{unsettled} ones, are peeled.
%
In the peel below, the \textit{key} of a settled vertex is its value, and the key of an unsettled vertex is its clique count.
%
At size $2$, the first size peeled, no vertex is settled.
\begin{theorem}[peel with settled vertices]\label{thm:settled}
Let every vertex $v$ with $\omg{v}\ge s$ be either settled, with key $\core{s}{v}$, or unsettled, with key its clique count.
%
Remove these vertices one at a time, each time one of smallest key, and give each the largest key seen at a removal so far.
%
Every such vertex receives its core value $\core{s}{v}$.
\end{theorem}
\begin{proof}
% 2026-09-23 proof check (codex exhaustive to 6 vertices with every bound, settled set and tie order; Fable 42,408 random peels): true; the maximality step, the empty case and the settled vertex's membership in D_k are now written.
Fix a level $k\ge1$, and let $D_k$ be the vertices of value at least $k$, the union of the cores of size $s$ at level $k$.
%
Every vertex of $D_k$ lies in at least $k$ $s$-cliques inside $D_k$.
%
Conversely, a set whose every vertex lies in $k$ or more $s$-cliques inside it lies inside $D_k$: each part connected through these cliques has both properties of Definition~\ref{def:nucleus} at level $k$.
%
Until a vertex of $D_k$ is removed, every vertex of $D_k$ has key at least $k$, since its value, or else its count, is at least $k$.
%
The first vertex of $D_k$ to be removed thus has key at least $k$, and a removal with key at least $k$ occurs whenever $D_k$ is not empty.
%
Just before the first removal with key at least $k$, the remaining vertices, call them $R$, include all of $D_k$.
%
Every vertex of $R$ has key at least $k$, and an unsettled one lies in at least $k$ $s$-cliques inside $R$ because its key is its count.
%
A settled one has value at least $k$ and lies in $D_k$, where it lies in at least $k$ $s$-cliques, all inside $R$.
%
By the converse, $R=D_k$, so exactly the vertices of $D_k$ receive a value of at least $k$, and every vertex receives $\core{s}{v}$.
\end{proof}
% 2026-09-23 proof check: why the settled vertices on no followed path can be left out; why a size without unsettled vertices ends the peels.
The peel never reads the count of a settled vertex, and a removal lowers the counts of the vertices that share a path with the removed vertex.
%
The peel of size $s$ thus follows the paths through unsettled vertices.
%
Removing a settled vertex that lies on none of these paths changes no key and happens at the smallest key, so leaving the vertex out changes no value.
%
Once a size has no unsettled vertex, every value there is a floor, and every vertex is settled at every later size.
%
Procedure \kw{Peel} of Algorithm~\ref{alg:peelsweep} is this peel at size $s$ with the set $S$ of settled vertices.
%
It keys the settled vertices by their floors and the others by their clique counts among the vertices with $\omg{v}\ge s$ (Lines~\ref{ln:p-init}--\ref{ln:p-count}).
%
It removes a vertex of smallest key, gives it the largest key seen so far (Lines~\ref{ln:p-min}--\ref{ln:p-give}), and recounts its unsettled neighbours, the only vertices whose counts the removal can change (Line~\ref{ln:p-update}).
\begin{example}\label{ex:settled}
% trace 2026-09-23: tools/example_check.py (settled and unsettled per size, 12 triangles through the unsettled vertices, all removed at level 3).
Consider Figure~\ref{fig:example} at size $3$.
%
The vertices $a_1,\dots,a_5$ and $b_1,b_2,b_3$ have their floors $4$ and $3$ as values at size $2$ (Example~\ref{ex:tail}), and they are settled with the floors $\binom{4}{2}=6$ and $\binom{3}{2}=3$.
%
The value of $x$ and of the six vertices $u_1,\dots,w_3$ at size $2$ is $4$, above their floors $3$ and $2$, and these seven vertices are unsettled.
%
The peel counts triangles only for them: $x$ lies in $12$, nine through $U$ and $W$ and three inside $B$, and each of the other six lies in $3$.
%
% 2026-09-23 proof check: the order among equal keys is free; the sentences hold for every order.
The smallest keys are $3$, of $u_1,\dots,w_3$ and of the settled $b_1,b_2,b_3$, and these nine vertices leave at level $3$.
%
Once $u_1,\dots,w_3$ are gone, $x$ lies in at most the three triangles of $B$, fewer if some $b_i$ left first, and it leaves at level $3$ as well.
%
No triangle joins $a_1,\dots,a_5$ to an unsettled vertex, and the peel never visits them.
%
At size $4$, $x$ is settled, since its value $3$ at size $3$ equals its floor $\binom{3}{2}$ there, and the $a_i$ and $b_i$ stay settled.
\end{example}

\stitle{The tree of a size.}
% 2026-09-24 user: Peel and Sweep need pseudocode; Algorithm alg:peelsweep holds both, Build calls them.
Procedure \kw{Sweep} of Algorithm~\ref{alg:peelsweep} builds the tree $\Tree{s}$ and the own nodes from the values of size $s$.
%
It activates the vertices from the highest value down (Lines~\ref{ln:w-levels}--\ref{ln:w-activate}).
%
An \textit{$s$-part} of a vertex set $A$ is a largest subset of $A$ connected through $s$-cliques inside $A$.
%
After each value $k$, the $s$-parts of the active vertices are the cores of size $s$ at level $k$, so an $s$-part that is not yet a node is a canonical node of top $k$ (Lines~\ref{ln:w-parts}--\ref{ln:w-node}).
%
Its children are the largest nodes inside it (Line~\ref{ln:w-children}), and every vertex of value $k$ receives its $s$-part as own node (Line~\ref{ln:w-own}).
%
The parts are found from the clique tree with one union per path and vertex.
%
A path is \textit{live} when its mandatory vertices are all active and at least $s$ of its vertices are active.
%
Every $s$-clique of active vertices lies on the one path that represents it, which is then live, and any $s$ active vertices of a live path form an $s$-clique of active vertices.
%
Joining the active vertices of every live path into one part therefore gives the $s$-parts of Line~\ref{ln:w-parts}.

\begin{algorithm}[t]
\caption{\kw{Peel} and \kw{Sweep} at size $s$.}\label{alg:peelsweep}
\SetAlgoLined\DontPrintSemicolon
\SetKwProg{Proc}{Procedure}{}{}
\SetKwFunction{Peel}{Peel}\SetKwFunction{Sweep}{Sweep}
\Proc{\Peel{$s,S$}}{
  $A\leftarrow\{v:\omg{v}\ge s\}$; $\ell\leftarrow0$\;\label{ln:p-a}
  $\mathrm{key}(v)\leftarrow\binomc{\omg{v}-1}{s-1}$, for every $v\in S$\;\label{ln:p-init}
  $\mathrm{key}(v)\leftarrow c_s(v,A)$, for every $v\in A\setminus S$\;\label{ln:p-count}
  \While{$A\ne\emptyset$}{
    $v\leftarrow$ a vertex of $A$ with the smallest key\;\label{ln:p-min}
    $A\leftarrow A\setminus\{v\}$; $\ell\leftarrow\max(\ell,\mathrm{key}(v))$; $\core{s}{v}\leftarrow\ell$\;\label{ln:p-give}
    $\mathrm{key}(u)\leftarrow c_s(u,A)$ for $u\in A\setminus S$ adjacent to $v$\;\label{ln:p-update}
  }
  \Return $\core{s}{\cdot}$\;
}
\Proc{\Sweep{$s$}}{
  $A\leftarrow\emptyset$; $\Tree{s}\leftarrow\emptyset$\;
  \ForEach{value $k$ of size $s$, in decreasing order}{\label{ln:w-levels}
    $B\leftarrow\{v:\core{s}{v}=k\}$; $A\leftarrow A\cup B$\;\label{ln:w-activate}
    \ForEach{$s$-part $K$ of $A$ with $K\notin\Tree{s}$}{\label{ln:w-parts}
      add $K$ to $\Tree{s}$ with top $k$\;\label{ln:w-node}
      $\mathrm{children}(K)\leftarrow$ the largest nodes of $\Tree{s}$ inside $K$\;\label{ln:w-children}
    }
    $\own{s}{v}\leftarrow$ the $s$-part of $A$ containing $v$, for $v\in B$\;\label{ln:w-own}
  }
  \Return $(\Tree{s},X_s)$\;
}
\end{algorithm}

\caption{\build: the chain index from one clique tree.}\label{alg:build}
\SetAlgoLined\DontPrintSemicolon
\KwIn{a graph $G$.}
\KwOut{\chainidx.}

\stitle{Algorithm.}
% 2026-09-24: the walk follows the abstract float; the layout steps point to Section 5, where they are defined.
Algorithm~\ref{alg:build} builds the clique tree once (Line~\ref{ln:b-tree}) and starts from one class holding every vertex (Line~\ref{ln:b-part}).
%
For every size (Line~\ref{ln:b-sizes}) it computes the values (Step 1) and the tree with the refinement of the classes (Step 2), and after the last size it lays out the index (Step 3).
%
\emph{During Step 1}, the algorithm collects the vertices settled at size $s$ (Line~\ref{ln:b-settle}).
%
Based on Theorem~\ref{thm:settled}, \kw{Peel} gives them their floors and peels only the other vertices (Line~\ref{ln:b-peel}).
%
\emph{During Step 2}, \kw{Sweep} builds $\Tree{s}$ and the own nodes of size $s$ (Line~\ref{ln:b-sweep}).
%
The algorithm then splits every class by the own node of size $s$, where $\own{s}{v}=\bot$ for a vertex of value $0$ (Line~\ref{ln:b-refine}).
%
After the last size, two vertices share a class exactly when they have the same own node at every size, so by Theorem~\ref{thm:chains} the classes are the chains.
%
Figure~\ref{fig:pipeline} draws this refinement as a trie, one level per size.
%
\emph{During Step 3}, the algorithm ranks the chains by the keys of Section~\ref{sec:order} and gives the vertices their labels (Line~\ref{ln:b-rank}).
%
It builds the run array and the entries of every size as in Section~\ref{sec:runs} (Line~\ref{ln:b-runs}).
%
It stores for every chain its clique number, its tail start, its residues and its trajectory, as in Section~\ref{sec:values} (Line~\ref{ln:b-values}).

\begin{example}\label{ex:build}
% trace 2026-09-21: tools/example_check.py (nodes, own nodes, chains); LEDGER.md (ranks, runs, entries).  2026-09-22: three sentences.
In Figure~\ref{fig:example} at size $2$, activating the value $4$ joins $A$ into one component and $\{x,u_1,\dots,w_3\}$ into another, the two nodes of top $4$.
%
Activating the value $3$ joins everything into the root of top $3$, and the partition then has three classes, $\{b_1,b_2,b_3\}$, $\{a_1,\dots,a_5\}$ and $\{x,u_1,\dots,w_3\}$.
%
At size $3$ no class is split.
%
At size $4$ the third class splits: $u_1,\dots,w_3$ have value $0$, and $x$ has the own node $B$.
%
The four classes, the dashed leaves of Figure~\ref{fig:pipeline}, are the chains of Example~\ref{ex:chains}, ranked $0$ to $3$ by their keys.
%
The layout of size $3$ produces the runs and entries of Figure~\ref{fig:layout}.
\end{example}

\stitle{Cost.}
% 2026-09-23: the shares are measured (Exp-1); the index passes are not "a few percent" (18-85 percent of the build).
% 2026-09-23 compaction: the time shares are measured in Exp-1 and not repeated here.
\kw{Sweep} adds, for every live path, one union per vertex that becomes active on it, and the refinement one step per vertex and size.
%
The layout adds one pass per size over the chains.
%
The working space is the clique tree and the graph, plus the values of two consecutive sizes, the partition, and the trees of the sizes with one node per canonical node.
%
The values take space linear in the vertices, the partition in the (chain, size) pairs, and the trees in the canonical nodes.
