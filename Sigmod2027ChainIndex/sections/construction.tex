\section{Construction}\label{sec:construction}

The index is built from one all-size peel and one pass per size, without ever holding all core values at once; the peel is ours and is described here so that the construction stands on its own.
Figure~\ref{fig:pipeline} shows the stages and what flows between them.

\stitle{Core values: one clique tree, every size.}
The counts come from a pivoting clique tree \cite{Pivoter}, built once: its paths partition the $s$-cliques of every size at the same time, a path with mandatory set $H$ and optional set $Q$ representing the cliques $H\cup X$ for $X\subseteq Q$, $|X|=s-|H|$, so the number of $s$-cliques of a vertex inside any vertex set is a sum of binomial coefficients over the paths through it.
The sizes are peeled in increasing order, and each size first tries to reuse the elimination order of the previous one.
Write $d_s(W,u)$ for the number of $s$-cliques of $u$ inside $G[W]$.
For a permutation $\pi=(v_0,\dots,v_{n-1})$ let $f_s(v_i)=d_s(\{v_i,\dots,v_{n-1}\},v_i)$, the $s$-cliques of $v_i$ inside its suffix, and $U_s(v_i)=\max_{j\le i}f_s(v_j)$.
Every $s$-clique is counted exactly once, at its earliest vertex in $\pi$, so $f_s$ is one sweep of the paths along $\pi$ with no propagation of losses.
\begin{theorem}[order replay]\label{thm:replay}
$U_s(v)\ge\core{s}{v}$ for every $v$, and $U_s=\core{s}{\cdot}$ at every vertex if and only if every $v$ has at least $U_s(v)$ $s$-cliques inside $\{u: U_s(u)\ge U_s(v)\}$.
\end{theorem}
\begin{proof}
For a witness $W\ni v$ let $v_j$ be its earliest vertex; $W$ lies in the suffix of $v_j$, so $\min_{u\in W}d_s(W,u)\le f_s(v_j)\le U_s(v)$.
If the condition holds, $W_k=\{u:U_s(u)\ge k\}$ has minimum $s$-degree at least $k$ for every level $k$ (a vertex $v$ of $W_k$ has its own set $\{u:U_s(u)\ge U_s(v)\}$ inside $W_k$), so the $s$-clique-connected component of $W_k$ containing $v$ is a level-$k$ witness and $\core{s}{v}\ge U_s(v)$.
Conversely, if $U_s$ is the core value, $\{u:\core{s}{u}\ge k\}$ is the union of the level-$k$ witnesses and has minimum $s$-degree at least $k$, which is the condition.
\end{proof}
When the certificate holds the size costs one sweep; when it fails the size is peeled exactly (a bucket peel that removes the vertex of smallest count and updates the paths through it in closed form), and the resulting order is the candidate for the next size.
The previous size's values also cap the next size's: the Kruskal--Katona shadow bound turns $\core{s-1}{v}$ into an upper bound on $\core{s}{v}$ that seeds the counts.
The values arrive one size at a time; the index keeps a two-row window, not the $s_{\max}\times n$ matrix.

\stitle{One tree per size, on arrival.}
When the values of size $s$ arrive, the vertices are activated from the highest value down.
A leaf of the clique tree becomes live when its mandatory vertices are active and at least $s$ of its vertices are active; the active vertices of a live leaf are pairwise adjacent inside a common clique, so they are joined in a union-find structure.
After each level the components that changed are the canonical nodes created at that level, and every activated vertex records its own node.
This is the pass that produces $\Tree{s}$ with tops, parents and own nodes.

\stitle{Chains by refinement.}
Chains are refined size by size in a prefix trie: at $s=2$ vertices are grouped by their own node; at each later size every group is split by the own node of that size; a vertex whose $\omega$ has been reached terminates at its current trie node.
The trie's DFS order, terminating chains before children, is the lexicographic key order of Section~\ref{sec:order}, so it yields the chain ranks, the aligned labels and the bitmap directly.
Working memory beyond the peel is one trie node per distinct own-node prefix and $O(n)$ words.

\stitle{Run arrays and values.}
For each size, the tree is traversed with children ordered by their smallest chain rank; the resulting chain sequence is merged into runs and every node's entry is recorded.
Each chain then receives $\omega$, its trajectory, and its values: $\sigma$ is the first size at which the chain's value equals the floor $\binomc{\omega-1}{s-1}$ (Theorem~\ref{thm:tail} says it stays there), only the values below $\sigma$ are stored as residues, and the per-size widths are chosen from the maxima.

\stitle{Cost.}
The peel and the clique tree dominate; the trie, the ranks, the run arrays and the values add a few percent (Section~\ref{sec:exp}).
Peak memory is the peel's clique tree plus the graph; the chain index itself is small.
