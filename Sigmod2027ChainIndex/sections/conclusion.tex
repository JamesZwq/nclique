\section{Conclusion}\label{sec:conclusion}
% 2026-09-21 house shape: the challenge nouns and the headline numbers verbatim; scope kept neutral.  Cadence pass.

In this paper, we presented \chainidx, an index for the $(1,s)$-nucleus hierarchies of every clique size at once.
%
We addressed the repetition across sizes, the contiguity of communities and the construction of every size.
%
The vertices no query can tell apart are exactly the chains, and chains are the coarsest lossless partition.
%
Aligned labels, a chain order and run arrays turn the partition into communities returned in constant time.
%
On \numgraphs{} graphs the index is \ratiomin$\times$ to \ratiomax$\times$ smaller than one hierarchy per size, median \ratiomedian$\times$.
%
It lists a community at the speed of a memory copy, and it is built for every size \priormin$\times$ to \priormax$\times$ faster than one decomposition per size.
%
Two case studies showed that the best size changes from query to query on DBLP and that the size zooms from a store to a shelf on Amazon.

\stitle{Scope.}
The index is static; maintenance under edge insertions beyond a rebuild is future work.
%
Its construction inherits the memory of the clique tree of the peel.
%
Three graphs whose trees exceed $350$~GB have no index yet, and a peel that streams the tree is the way to them.
%
Values are stored as doubles, exact below $2^{53}$, which covers every value on our graphs.
%
The partition is stated for vertices.
%
Hierarchy equivalence of edges and larger cliques is defined the same way, and an index over it is future work.
