\section{\texorpdfstring{Computing Core Values over Static \cpi}{Computing Core Values over Static CPI}}\label{sec:hindex}

The $(1,s)$-nucleus core number of a vertex is the largest level at which it sustains enough $s$-cliques inside a maximal vertex set, so the entire computation reduces to counting $s$-cliques inside vertex sets.
%
This section organizes the algorithms around that single primitive.
%
Section~\ref{sec:setsupport} names it the \emph{set support} $\setSup_R(v)$ and shows that the static \cpi{} evaluates it without enumerating any clique.
%
The next two subsections exercise $\setSup_R$ in complementary ways.
%
\spin{} (Section~\ref{sec:localh}) is the direct fixed-point specification: it recomputes $\setSup_R$ from scratch every pass on a sequence of threshold-induced sets and lifts the core values out of the converged vector.
%
\spinStar{} (Section~\ref{sec:peelh}) is the change-only version of this specification.
%
It maintains $\setSup_R$ on a single mutable residual set, and updates only the support losses caused by each deletion.
%
Section~\ref{sec:changeonly-impl} closes the loop by showing how the static \cpi{} delivers those losses in closed form.

\subsection{Set support over the static \cpi}\label{sec:setsupport}

We begin by isolating the one quantity that both algorithms compute, then show how the static \cpi{} produces it.

\begin{definition}[Anchored set support]\label{def:set-support}
For an anchor vertex $v\in V$ and a vertex set $R\subseteq V$, the \emph{set support} of $v$ relative to $R$ is
\[
  \setSup_R(v) \;=\; \bigl|\{C\subseteq V : v\in C,\ |C|=s,\ C\text{ is a clique in } G,\ C\setminus\{v\}\subseteq R\}\bigr|.
\]
The focal vertex $v$ is anchored: only the \emph{other} $s\!-\!1$ vertices of each counted clique are required to lie in $R$, and $v$ itself need not belong to $R$.
%
When $v\in R$, $\setSup_R(v)$ equals $v$'s usual $s$-clique support inside the induced subgraph $G[R]$; the full-graph case recovers $s$-degree, $\setSup_V(v)=\sdeg(v)$.
\end{definition}

Anchoring $v$ is what lets one operator serve both algorithms.
%
\spin{} queries $\setSup_R$ on threshold-induced sets, where $v$ may sit on the boundary.
%
\spinStar{} maintains $\setSup_R$ on a residual set, where every unfinalised vertex lies in $R$.
%
What remains is to evaluate $\setSup_R(v)$ without enumerating cliques.

The static \cpi{} delivers the evaluation locally.
%
Every encoded $s$-clique sits on a unique path $\TPath$.
%
It counts toward $\setSup_R(v)$ exactly when its other $s\!-\!1$ vertices lie in $R$.
%
Equivalently, the path's hold set excluding $v$ must lie in $R$, and the required pivots must be drawn from $\Vp(\TPath)\cap R$, excluding $v$ if $v$ is itself a pivot.
%
The next lemma turns this observation into a closed sum of binomials, one term per path through $v$.

\begin{lemma}[\cpi{} evaluation of set support]\label{lem:set-support-eval}
For any $v\in V$ and $R\subseteq V$,
\[
  \setSup_R(v) \;=\; \sum_{\TPath\ni v} \mathbf{1}\bigl[\Vh(\TPath)\setminus\{v\}\subseteq R\bigr]\cdot\pathContrib\bigl(\TPath,v,|(\Vp(\TPath)\setminus\{v\})\cap R|\bigr).
\]
\end{lemma}

\begin{proof}
Every $s$-clique containing $v$ is encoded by a unique path $\TPath$ as $\Vh(\TPath)\cup P'$ with $P'\subseteq\Vp(\TPath)$ and $|P'|=\eta_{\TPath}$ (Definition~\ref{def:path}).
%
Such a clique counts toward $\setSup_R(v)$ iff its other $s\!-\!1$ vertices lie in $R$, i.e.\ $\Vh(\TPath)\setminus\{v\}\subseteq R$ and $P'\setminus\{v\}\subseteq R$.
%
Conditioned on the hold inclusion, the count of qualifying $P'$ is $\pathContrib(\TPath,v,|(\Vp(\TPath)\setminus\{v\})\cap R|)$ by Definition~\ref{def:path-contrib}: when $v\in\Vp(\TPath)$, $v$ itself fills one of the $\eta_{\TPath}$ pivot slots and the remaining $\eta_{\TPath}\!-\!1$ are chosen from the pivot scope excluding $v$.
%
Summing over the paths through $v$ gives the stated total.
%
\qed
\end{proof>

Two evaluation regimes follow from this lemma.
%
For a fixed $R$ represented by membership bits, $\setSup_R(v)$ is one scan of $v$'s incident paths and runs in time $O(w_v)$, with $w_v=\sum_{\TPath\ni v}(|\Vh(\TPath)|+|\Vp(\TPath)|)$ the incidence weight of $v$ in the static \cpi{}.
%
\spin{} needs many threshold counts $\setSup_{R_h(k)}(v)$ in one go; sorting each scanned path's vertex values once and reading the thresholds off prefix sums delivers every $\setSup_{R_h(k)}(v)$ in a single pass per path, at per-call cost $O(w_v\log L_{\max})$ with $L_{\max}=\max_{\TPath}(|\Vh(\TPath)|+|\Vp(\TPath)|)$.
%
Either regime touches the static \cpi{} read-only.

\subsection{\texorpdfstring{\spin{}: direct fixed-point specification}{SPIN: direct fixed-point specification}}\label{sec:localh}

The direct route from $\setSup_R$ to $\kappa_s$ is self-referential: vertex $v$ deserves level $k$ exactly when it has $k$ supporting $s$-cliques whose other vertices also sustain level $k$.
%
We make the self-reference precise and let the fixed point do the rest.

Given a tentative value vector $h$, the threshold-induced set
\[
  R_h(k) \;=\; \{u\in V : h[u]\ge k\}
\]
collects every vertex that currently sustains level $k$, and the one-vertex update returns the largest level $v$ can claim from those survivors:
\[
  \Phi_h(v) \;=\; \max\bigl\{k\ge 0 \;:\; \setSup_{R_h(k)}(v)\ge k\bigr\}.
\]
\spin{} initialises $h[v]\gets\setSup_V(v)=\sdeg(v)$ and repeatedly applies $\Phi_h$ to every vertex until the vector stops changing.
%
The initial vector pointwise dominates the final core values, and each pass only lowers entries.
%
The iteration is therefore monotone and terminates.
%
The converged vector serves as the canonical semantic anchor for any static-\cpi{} core-value solver.

\begin{algorithm}[t]
\algfontsize
\caption{\spin{}: direct fixed-point iteration over set support.}
\label{alg:localH}
\KwIn{Graph $G$, clique size $s$, \cpi{} $\mathcal{P}$.}
\KwOut{$\kappa_s(v)$ for every $v\in V$.}

\lForEach{$v\in V$}{$h[v]\gets\setSup_V(v)$}
$\mathrm{changed}\gets\textsf{true}$\;
\While{$\mathrm{changed}$}{
    $\mathrm{changed}\gets\textsf{false}$;\quad $h_{\mathrm{new}}\gets h$\;
    \ForEach{$v\in V$ \emph{in a fixed order}}{
        $h_{\mathrm{new}}[v]\gets\max\bigl\{k\le h[v] : \setSup_{R_h(k)}(v)\ge k\bigr\}$\tcp*{Lemma~\ref{lem:set-support-eval}}
        \lIf{$h_{\mathrm{new}}[v]\ne h[v]$}{$\mathrm{changed}\gets\textsf{true}$}
    }
    $h\gets h_{\mathrm{new}}$\;
}
\lForEach{$v\in V$}{$\kappa_s(v)\gets h[v]$}
\Return{$\kappa_s$}
\end{algorithm}

The iteration is short on small instances: a single pass already drops every vertex to its core value on the running example.

The first $\Phi_h$ evaluation at $v_4$ tests, for descending $k$, whether $\setSup_{R_h(k)}(v_4)\ge k$ using Lemma~\ref{lem:set-support-eval}; the largest passing $k$ is $3$, so $h[v_4]$ drops $6\!\to\!3$.

The example agrees with the general guarantee: the iteration always terminates at the $(1,s)$-core values.

\begin{lemma}[\spin{} Convergence]\label{lem:hindex-convergence}
Initialised at $h^{(0)}[v]=\sdeg(v)$, Algorithm~\ref{alg:localH} terminates in finitely many passes with $h[v]=\kappa_s(v)$ for every $v\in V$, and the sequence $h^{(t)}[v]$ is monotonically non-increasing.
\end{lemma}

\begin{proof}
By the operator definition, $h^{(t+1)}[v]\!\ge\!k$ iff $v$ has at least $k$ incident $s$-cliques inside $R_{h^{(t)}}(k)$, so $\sdeg(v)$ is the largest possible value and the sequence is monotone non-increasing on the non-negative integers.
%
The sequence is bounded below by $0$ and decreases by at least one in any non-converged pass, so the iteration terminates and a pass with no entry change certifies the converged vector $h^\star$.
%
At $h^\star$, let $S_k=R_{h^\star}(k)$, and let $C\subseteq S_k$ be $v$'s $s$-connected component within $S_k$.
%
Every $v\!\in\!S_k$ has $\setSup_{S_k}(v)\ge k$, and each such clique places $v$ in $C$ (the clique itself provides the link), giving Conditions~(i) and (ii) of Definition~\ref{def:nucleus}.
%
For (iii), suppose for contradiction that some $w\!\notin\!C$ could be added to $C$ while preserving (i) and (ii); then $w$ has at least $k$ $s$-cliques whose other vertices lie in $C\subseteq S_k$.
%
By the anchored support of Definition~\ref{def:set-support}, $\setSup_{S_k}(w)\ge k$, so $\Phi_{h^\star}(w)\ge k$ and hence $h^\star[w]\ge k$, placing $w\in S_k$.
%
Moreover each such clique links $w$ to $C$-vertices inside $S_k$, so $w\in C$, a contradiction.
%
Hence $C$ is a $k$-$(1,s)$-nucleus, giving $\kappa_s(v)\!\ge\!k$.
%
Conversely, if $v$ lies in a $k$-$(1,s)$-nucleus $C'$, we show by induction on $t$ that $h^{(t)}[u]\!\ge\!k$ for every $u\!\in\!C'$.
%
The base case $t\!=\!0$ holds since each $u\!\in\!C'$ is in at least $k$ $s$-cliques inside $C'$, so $h^{(0)}[u]\!=\!\sdeg(u)\!\ge\!k$.
%
For the inductive step, $C'\subseteq R_{h^{(t)}}(k)$ implies $\setSup_{R_{h^{(t)}}(k)}(u)\!\ge\!\setSup_{C'}(u)\!\ge\!k$, so $h^{(t+1)}[u]\!\ge\!k$.
%
Therefore $h^\star[v]\!\ge\!k$, and hence $h^\star[v]=\kappa_s(v)$.
%
\qed
\end{proof}

The cost is the per-pass work, one $\setSup$ evaluation per vertex, multiplied by the number of passes.

\begin{theorem}[\spin{} Complexity]\label{thm:localh-complexity}
Algorithm~\ref{alg:localH} computes $\kappa_s$ in $O(T\cdot\Sig\cdot L_{\max}\cdot\log L_{\max})$ work, where $\Sig$ is the static \cpi{}'s total vertex--path incidence count (Section~\ref{sec:prelim}), $T$ is the number of passes until convergence, and $L_{\max}$ is the maximum path size.
\end{theorem}

\begin{proof}
Each pass evaluates $\Phi_h(v)$ for every $v\in V$ at per-call cost $O(w_v\log L_{\max})$ (Section~\ref{sec:setsupport}).
%
Summing, $\sum_v w_v=\sum_{\TPath}|\TPath|^2\le L_{\max}\cdot\Sig$, so each of the $T$ passes costs $O(\Sig\cdot L_{\max}\cdot\log L_{\max})$.
%
\qed
\end{proof}

Two patterns of waste in this cost motivate the next subsection.

\begin{remark}[Inefficiencies of \spin{}]\label{rem:spin-ineff}
\spin{} pays two kinds of redundant work.
%
First, it re-evaluates $\Phi_h$ on every vertex in every pass.
%
A vertex may reach its final value in the first pass, yet still be refreshed in later passes.
%
Second, each evaluation recomputes $\setSup_{R_h(k)}$ from scratch over all paths through $v$.
%
It repeats this work across thresholds, and often repeats binomial counts from earlier passes.
\end{remark}

\subsection{\texorpdfstring{\spinStar{}: change-only peeling}{SPIN-star: change-only peeling}}\label{sec:peelh}

\spin{} is clean as a specification but wasteful as an algorithm (Remark~\ref{rem:spin-ineff}).
%
The waste has a local structure: support changes are caused by vertices leaving the relevant supporting set, and each such change affects only cliques on paths through those vertices.
%
This locality suggests a different execution schedule.
%
Rather than recomputing all set supports each pass, update only the support lost after each deletion.
%
\spinStar{} turns this locality into \emph{change-only peeling} on a single mutable residual set.

\stitle{Single mutable residual.}
Instead of induced sets that come and go, \spinStar{} tracks one set throughout: the \emph{residual set} $R$, initialised to $V$ and shrunk by one vertex per pop in deletion order.
%
For every unfinalised $v$ it maintains the invariant $\supArr[v]=\setSup_R(v)$, the exact set support on the current residual.

\stitle{Change-only delta.}
When $R$ shrinks to $R\setminus\{x\}$, only vertices $u$ that share an encoded $s$-clique with $x$ can lose support; for every such $u$, the support drop is
\[
  \Delta_x(u) \;=\; \setSup_R(u) - \setSup_{R\setminus\{x\}}(u).
\]
\spinStar{} touches only the affected $u$ and applies $\supArr[u]\gets\supArr[u]-\Delta_x(u)$, instead of recomputing $\setSup$ on the new residual.
%
Section~\ref{sec:changeonly-impl} shows how the static \cpi{} delivers $\Delta_x(u)$ in closed form by walking the paths through $x$ once.

\stitle{Peel-order schedule.}
Pops are ordered by the priority-queue key $\keyArr[v]=\max(k_{\mathrm{cur}},\supArr[v])$, where $k_{\mathrm{cur}}$ is the current peel level.
%
The clip lifts the queue value when the residual support has already fallen below the current level.
%
This keeps the extracted-key sequence monotone non-decreasing.
%
Each pop's $k$ is therefore the popped vertex's final $\kappa_s$, and the whole peel completes in a single deletion pass.

\begin{algorithm}[t]
\algfontsize
\caption{\spinStar{}: change-only peeling over set support.}
\label{alg:peelH}
\KwIn{Graph $G$, clique size $s$, \cpi{} $\mathcal{P}$.}
\KwOut{$\kappa_s(v)$ for every $v\in V$.}

$R\gets V$\;
\lForEach{$v\in V$}{$\supArr[v]\gets\setSup_R(v)$;\quad $\keyArr[v]\gets\supArr[v]$}
$Q\gets$ min-priority queue with key $\keyArr[\cdot]$; insert each $v\in V$\;
\While{$R\ne\emptyset$}{
    $(v,k)\gets Q.\textsc{extract-min}()$\;
    $\kappa_s(v)\gets k$;\quad $R\gets R\setminus\{v\}$\;
    \ForEach{$u\in R$ \emph{with} $\Delta_v(u)\ne 0$}{
        $\supArr[u]\gets\supArr[u]-\Delta_v(u)$\tcp*{$\Delta_v(u)$ realized by per-path losses (Lemma~\ref{lem:changeonly-cpi})}
        $y\gets\max\{k,\,\supArr[u]\}$\;
        \lIf{$y<\keyArr[u]$}{$Q.\textsc{decrease-key}(u,y)$;\quad $\keyArr[u]\gets y$}
    }
}
\Return{$\kappa_s$}
\end{algorithm}

Algorithm~\ref{alg:peelH} initialises $R\!=\!V$, $\supArr[v]\!=\!\setSup_V(v)\!=\!\sdeg(v)$, and seeds the priority queue with $\keyArr[\cdot]$ (Lines~1-3).
%
The peel loop (Lines~4-9) extracts the minimum-key vertex $v$ at peel level $k$, finalizes $\kappa_s(v)\!\gets\!k$, removes $v$ from $R$, and propagates the change-only delta $\Delta_v$ to every affected unfinalised $u$ (Line~7); each $\supArr[u]$ is decremented (Line~8) and $u$'s priority-queue key is lifted via $\textsc{decrease-key}$ when the clipped value drops (Line~9).
%
Because $\keyArr[u]\ge k$ for every unfinalised $u$ and $k$ is non-decreasing across extractions, the extracted-key sequence is monotone, so each pop assigns its final $\kappa_s$ value~\cite{coreAlg}.

We trace one pop on the running example to make the change-only delta concrete.

\begin{example}\label{ex:peelh}
Same setup as Example~\ref{ex:hop}.
%
At iteration~$1$ the four pendant-triangle vertices $v_7,v_8,v_9,v_{10}$ tie at minimum key $1$; suppose $v_8$ pops first at $k\!=\!1$.
%
Removing $v_8$ from $R$ retires $\TPath_1$ (since $\Vp(\TPath_1)\cap R$ loses its only spare pivot, killing the path); the affected co-path vertices are $v_7$ (hold of $\TPath_1$, loses $\binom{2}{2}\!=\!1$) and $v_6$ (pivot of $\TPath_1$, loses $\binom{1}{1}\!=\!1$).
%
At iteration~$7$ the extracted key reaches $k\!=\!3$ and $v_4$ pops, sending change-only deltas through the two live paths $\TPath_5$ and $\TPath_6$ as in Lemma~\ref{lem:changeonly-cpi}.
%
After ten pops, $\kappa_3(v_i)\!=\!3$ for $i\!\in\!\{1,\ldots,6\}$ and $\kappa_3(v_i)\!=\!1$ for $i\!\in\!\{7,\ldots,10\}$; Table~\ref{tab:peel} traces $\supArr$ across the ten iterations.
\end{example}

Correctness reduces to a single invariant: $\supArr$ always equals the true residual set support.

\begin{lemma}[Change-only peeling preserves the \spin{} fixed point]\label{lem:equivalence}
Algorithm~\ref{alg:peelH} returns the same $\kappa_s$ values as Algorithm~\ref{alg:localH}.
\end{lemma}

\begin{proof}
We establish the \emph{residual-support invariant}: at every iteration of the peel loop, $\supArr[u]=\setSup_R(u)$ for every $u\in R$.

\smallskip
\noindent\emph{(i) Initialisation.}
At $t=0$, $R=V$ and $\supArr[v]\!\gets\!\setSup_V(v)$ directly (Definition~\ref{def:set-support}).

\smallskip
\noindent\emph{(ii) Inductive step.}
Assume the invariant holds when $v$ is popped.
%
Removing $v$ from $R$ changes $\setSup_R(u)$ to $\setSup_{R\setminus\{v\}}(u)=\setSup_R(u)-\Delta_v(u)$ for every other $u\in R$, by Definition~\ref{def:set-support}.
%
Algorithm~\ref{alg:peelH} subtracts exactly $\Delta_v(u)$ from $\supArr[u]$ (Line~8), restricted to $u$ with $\Delta_v(u)\!\ne\!0$ (Line~7) since other vertices' supports are unchanged.
%
After the iteration, $\supArr[u]=\setSup_{R\setminus\{v\}}(u)$ on the new residual, preserving the invariant.

\smallskip
\noindent\emph{(iii) Peel correctness.}
Algorithm~\ref{alg:peelH} follows the standard deletion-order peeling template for $(1,s)$-core decomposition~\cite{coreAlg,nucleusSariyuce14}.
%
At each iteration it finalizes the unfinalised vertex of minimum clipped support $\max\{k_{\mathrm{cur}},\supArr[u]\}$, then removes that vertex's set-support contribution from the residual graph.
%
The clip $\keyArr[u]\gets\max\{k,\supArr[u]\}$ (Line~9) does not alter $\supArr[u]$; it only changes the priority-queue key.
%
It enforces non-decreasing extraction when residual support falls below the current peel level.
%
By the standard correctness of counting-based core decomposition for $(r,s)$-nucleus~\cite{nucleusSariyuce14}, each popped vertex's $k$ equals its $(1,s)$-nucleus core number.

\smallskip
By Lemma~\ref{lem:hindex-convergence}, this $\kappa_s$ vector is the same fixed point reached by \spin{}.
%
\qed
\end{proof}

The cost splits into three pieces along the three phases of each pop: walking the incident paths, applying binomial arithmetic at the affected co-path vertices, and updating the priority queue.

\begin{theorem}[\spinStar{} Complexity]\label{thm:peelh-complexity}
Algorithm~\ref{alg:peelH} runs in $O(\Sig+(U+n)\log n)$ time, where $\Sig$ is the total vertex--path incidence count of the static \cpi{} and $U$ is the total number of nonzero per-path loss evaluations emitted by change-only peeling.
\end{theorem}

\begin{proof}
Initialisation evaluates $\setSup_V$ for every $v$ at total cost $O(n+\Sig)$, by the amortised bound of Lemma~\ref{lem:set-support-eval} (each vertex--path incidence is touched once).
%
The $n$ priority-queue insertions cost $O(n\log n)$.
%
Walking the incident path lists across all pops costs $O(\Sig)$, because each vertex--path incidence is scanned exactly once when its vertex pops.
%
For each changed co-path incidence, Lemma~\ref{lem:changeonly-cpi} performs one constant-time binomial loss computation, contributing $O(U)$ arithmetic work in total.
%
The $n$ extract-min operations and at most $U$ decrease-key operations cost $O((U+n)\log n)$.
%
The total is $O(\Sig+U+(U+n)\log n)=O(\Sig+(U+n)\log n)$.
%
\qed
\end{proof}

The bound is sharp in $\Sig$ but parameterized by $U$; a straightforward incidence argument closes the worst case.

\begin{corollary}[Worst-case bound on $U$]\label{cor:U-bound}
$U\le L_{\max}\cdot\Sig$, where $L_{\max}=\max_{\TPath}(|\Vh(\TPath)|+|\Vp(\TPath)|)$.
%
Hence Algorithm~\ref{alg:peelH} runs in $O(\Sig\cdot L_{\max}\cdot\log n)$ time in the worst case.
\end{corollary}

\begin{proof}
For each path $\TPath$ and each incident vertex $u$, change-only peeling can emit a per-path loss for $u$ only when another vertex on $\TPath$ is popped.
%
Thus $u$ receives at most $|\TPath|-1$ per-path losses from $\TPath$.
%
Summing over $(\TPath,u)$ pairs gives $U\le\sum_{\TPath}|\TPath|\cdot(|\TPath|-1)\le L_{\max}\cdot\Sig$.
%
Substituting into Theorem~\ref{thm:peelh-complexity} yields the worst-case bound.
%
\qed
\end{proof}

\subsection{Static-\cpi{} implementation of change-only updates}\label{sec:changeonly-impl}

Algorithm~\ref{alg:peelH} leaves one mechanism abstract: how does the static \cpi{} produce $\Delta_v(u)$ without re-evaluating $\setSup$ on the shrunken residual?
%
The answer is local.
%
The cliques that disappear from $u$'s support when $v$ leaves $R$ are exactly those encoded by a path containing both $v$ and $u$, alive in $G[R]$.
%
Thus the affected vertices are the co-path neighbors of $v$ in the static \cpi{}.
%
Each $\Delta_v(u)$ decomposes into a sum over the shared paths.
%
Every per-path term is a binomial difference computable in $O(1)$.

\begin{lemma}[\cpi{} realization of the change-only delta]\label{lem:changeonly-cpi}
Let $v\in R$ be popped and $u\in R\setminus\{v\}$.
%
Then
\[
  \Delta_v(u) \;=\; \sum_{\substack{\TPath\ni v,u \\ \TPath \text{ alive in } G[R]}} \pathDelta(\TPath, u, v),
\]
where for a path $\TPath$ alive in $G[R]$ with pre-pop pivot scope $p_{\mathrm{old}}=|\Vp(\TPath)\cap R|\ge\eta_{\TPath}$ and post-pop scope $p_{\mathrm{new}}=p_{\mathrm{old}}-\mathbf{1}[v\in\Vp(\TPath)]$, the per-path contribution is the binomial differential
\[
  \pathDelta(\TPath,u,v) \;=\;
  \begin{cases}
    \pathContrib(\TPath,u,q_{\mathrm{old}}), & v\in\Vh(\TPath) \text{ or } p_{\mathrm{new}}<\eta_{\TPath}, \\
    \pathContrib(\TPath,u,q_{\mathrm{old}}) - \pathContrib(\TPath,u,q_{\mathrm{new}}), & v\in\Vp(\TPath) \text{ and } p_{\mathrm{new}}\ge\eta_{\TPath},
  \end{cases}
\]
with the $u$-aware scopes
\[
  q_{\mathrm{old}}=p_{\mathrm{old}}-\mathbf{1}[u\in\Vp(\TPath)],\qquad
  q_{\mathrm{new}}=p_{\mathrm{new}}-\mathbf{1}[u\in\Vp(\TPath)].
\]
%
Each $\pathDelta$ evaluates in $O(1)$ via a precomputed binomial table, so applying all $\Delta_v(\cdot)$ updates for one pop costs $O\bigl(\sum_{\TPath\ni v}(|\Vh(\TPath)|+|\Vp(\TPath)|)\bigr)$.
\end{lemma}

\begin{proof}
By Lemma~\ref{lem:set-support-eval} applied at $R$ and $R\setminus\{v\}$,
\[
  \Delta_v(u)=\setSup_R(u)-\setSup_{R\setminus\{v\}}(u)=\sum_{\TPath\ni u}\bigl[W_{\TPath}^{R}(u)-W_{\TPath}^{R\setminus\{v\}}(u)\bigr],
\]
where the anchored per-path contribution is
\[
  W_{\TPath}^{R}(u)=\mathbf{1}\bigl[\Vh(\TPath)\setminus\{u\}\subseteq R\bigr]\cdot\pathContrib\bigl(\TPath,u,|(\Vp(\TPath)\setminus\{u\})\cap R|\bigr).
\]
A path $\TPath$ with $v\notin\TPath$ has identical hold inclusion and pivot scope in $R$ and $R\setminus\{v\}$, contributing $0$; the sum reduces to paths through both $v$ and $u$.
%
For such a path with $v\in\Vh(\TPath)$, deleting $v$ from $R$ breaks the hold-inclusion check for $u$ (since $v\ne u$ lies in $\Vh(\TPath)\setminus\{u\}$), killing the second term and giving the killed case.
%
For $v\in\Vp(\TPath)$, the hold-inclusion check is unaffected, and the $u$-aware pivot scope drops from $q_{\mathrm{old}}$ to $q_{\mathrm{new}}=q_{\mathrm{old}}-1$; the differential is $\pathContrib(\TPath,u,q_{\mathrm{old}})-\pathContrib(\TPath,u,q_{\mathrm{new}})$, with the second term vanishing by the binomial convention $\binom{m}{j}=0$ for $j>m$ when $p_{\mathrm{new}}<\eta_{\TPath}$.
%
The cost claim follows because each co-path incidence $(\TPath,u)$ with $\TPath\ni v$ is visited once for this pop, and each visit performs one $O(1)$ binomial evaluation.
%
\qed
\end{proof}

In Algorithm~\ref{alg:peelH}, the iteration over ``$u\in R$ with $\Delta_v(u)\ne 0$'' (Line~7) is realized by walking every alive path $\TPath\ni v$ and visiting its co-path vertices.
%
The only mutable per-path state is the pivot counter $p_{\TPath}$; the requirement $\eta_{\TPath}$ is fixed, and the path is alive iff $p_{\TPath}\ge\eta_{\TPath}$, with $p_{\TPath}\gets-1$ marking a hold-peeled path.
