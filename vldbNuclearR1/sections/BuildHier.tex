\section{Core-Value Hierarchy Construction}\label{sec:buildhier}

After \spinStar{} computes the core values, we extract the $(1,s)$-clique-connected nucleus hierarchy of Definition~\ref{def:nucleus} from the preserved \cpi{} of Section~\ref{sec:static}.
%
For any level $k$, the super-level set is $V_k=\{v\mid \kappa_s(v)\ge k\}$ and Definition~\ref{def:nucleus} measures connectivity inside $V_k$ through $s$-clique witnesses contained in $V_k$; \buildHier{} (Algorithm~\ref{alg:buildhier}) constructs the elder-rule join tree of this clique-witnessed filtration directly from \cpi{} leaves in a single descending union--find scan, in $O(\Sig\log\Sig)$ time and without re-enumerating any clique.

\stitle{Leaves as connectors.}
A \cpi{} leaf $P$ encodes the family of $s$-cliques $\Vh(P)\cup X$ for every $\eta_P$-subset $X\subseteq\Vp(P)$ (Definition~\ref{def:path}).
%
Define the \emph{birth level} of $P$ as
\[
  k_P \;=\; \min_{v\in\Vh(P)\cup\Vp(P)}\kappa_s(v).
\]
%
At level $k\le k_P$ every leaf vertex has core value at least $k$, so every encoded $s$-clique is contained in $V_k$.
%
Any two vertices of the leaf either lie inside one such clique (when $\eta_P\ge2$) or are linked by a length-two path through a vertex of $\Vh(P)$ (when $\eta_P=1$ and $\Vh(P)$ is non-empty); for $\Vh(P)=\emptyset$ and $\eta_P\ge2$, any pair appears together in some $s$-subset.
%
In every case the leaf vertices form a single $s$-connected component the moment $P$ becomes active.
%
This lets \buildHier{} treat each leaf as a single hyperedge in a union--find structure: the leaf node is unified with every vertex it contains.
%
Two vertices then end up in the same component if and only if they are $s$-connected through active \cpi{} cliques at the current level.

\stitle{Reverse scan over leaves.}
\buildHier{} processes leaves in nonincreasing $k_P$, as the level descends through the filtration.
%
A union--find structure spans both vertices and leaf identifiers; processing leaf $P$ at its birth level fires unions $\textsc{Union}(P,v)$ for every $v\in\Vh(P)\cup\Vp(P)$.
%
A birth level is recorded for each component root, so a merge applies the elder rule.
%
Vertices not appearing in any leaf with $k_P\ge1$ have $\kappa_s(v)=0$ and are omitted from the hierarchy.

\begin{algorithm}[t]
\algfontsize
\caption{\buildHier{} --- elder-rule join tree atop \spinStar{}.}
\label{alg:buildhier}
\KwIn{Graph $G$, clique size $s$, \cpi{} $\mathcal{P}$.}
\KwOut{Elder-rule join tree $T$ of the $s$-clique-connected super-level filtration.}

$\kappa_s \gets \spinStar{}(G, s, \mathcal{P})$ \tcp*{Algorithm~\ref{alg:peelH}}
\ForEach{leaf $P\in\mathcal{P}$}{
    $k_P \gets \min\{\kappa_s(v)\mid v\in\Vh(P)\cup\Vp(P)\}$\;
}
sort $\mathcal{P}$ by nonincreasing $k_P$ (ties broken by leaf id)\;
initialise union-find $U$ over $V\cup\{P\mid P\in\mathcal{P}\}$; $\text{birth}[r]\gets+\infty$ for every root $r$\;
$T\gets$ empty forest\;
\ForEach{leaf $P$ in sorted order}{
    $R\gets\{\textsc{Find}(x)\mid x\in\Vh(P)\cup\Vp(P)\cup\{P\}\}$\;
    \ForEach{root $r\in R$}{
        \If{$\text{birth}[r]=+\infty$}{
            emit a hierarchy node $n_r$ with $k_{\mathrm{birth}}\gets k_P$; $\text{birth}[r]\gets k_P$\;
        }
    }
    \If{$|R|\ge2$}{
        sort $R$ descending by $(\text{birth}[r], |r|)$; let $r^\star$ be the elder \tcp*{elder rule}
        \ForEach{$r\in R\setminus\{r^\star\}$}{
            attach $n_r$ as child of $n_{r^\star}$ at level $k_P$ in $T$ \tcp*{younger dies}
        }
        $\textsc{Union}$ all of $R$ into a single component\;
    }
}
\Return{$T$}
\end{algorithm}

Algorithm~\ref{alg:buildhier} first invokes \spinStar{} to compute the core values (Line~1), then assigns each leaf its birth level $k_P$ as the minimum core value among its hold and pivot vertices (Lines~2-3).
%
Leaves are sorted by nonincreasing $k_P$ (Line~4) so they fire in descending peel order, and the union--find structure is initialised over both vertices and leaf identifiers with all roots born at $+\infty$ (Line~5).
%
For each leaf $P$ in sorted order (Lines~7-13), the algorithm collects the current root set $R$ of every vertex in $P$ together with the leaf itself (Line~8), emits a fresh hierarchy node for any root that has not been born yet (Lines~9-11), applies the elder rule when $|R|\ge2$ by selecting the earliest-born root $r^\star$ and attaching the others as its children at level $k_P$ (Lines~12-14), and finally unifies all roots into a single component (Line~15).
%
The returned forest $T$ is the elder-rule join tree.

\stitle{Correctness.}
The descending scan visits each leaf at exactly the level it first contributes $s$-cliques contained in the current super-level set.
%
At that level, every vertex it contains lies in the super-level set, so the leaf witnesses pairwise $s$-connectivity for all of them through a common element of $\Vh(P)$ (or directly within an $s$-subset when $\Vh(P)=\emptyset$).
%
Conversely, every active $s$-clique at level $k$ belongs to some leaf with $k_P\ge k$, and that leaf has already fired before the scan reaches level $k$; so every $s$-clique-connected merge of Definition~\ref{def:nucleus} is performed.
%
When two distinct components meet at a leaf, the elder rule preserves the component with earlier birth and attaches the younger one in the join tree~\cite{morozov2007persistence}.

\stitle{Complexity.}
Computing every $k_P$ and sorting leaves costs $O(\Sig+L\log L)$, where $L=|\mathcal{P}|$.
%
Each leaf fires at most $|\Vh(P)|+|\Vp(P)|$ union-find operations, summing to $O(\Sig\,\alpha(n+L))$ over all leaves.
%
Total time $O(\Sig\log\Sig)$, dominated by the sort, with no clique re-enumeration: \buildHier{} reads each \cpi{} leaf at most twice (once to compute $k_P$, once to fire unions).

\stitle{Memory.}
Beyond the union-find of size $n+L$, the routine needs a list of vertices per leaf to fire unions.
%
\spinStar{}'s vertex-to-leaf inverse CSR (Section~\ref{sec:hindex}) supports a single bucket-CSR pass that materialises the per-leaf lists in $O(\Sig)$ temporary memory; this scratch is freed on return.
%
The static \cpi{} budget of Section~\ref{sec:exp} therefore holds throughout peeling proper and is only briefly elevated during the hierarchy emit.

\stitle{Consequence.}
The clique-coherent core-value hierarchy is not a separate decomposition problem in this pipeline.
%
It is a byproduct of the static \cpi{} surviving peeling: leaves act as hyperedges of an implicit $s$-clique witness graph, and a single descending pass with union--find produces the join tree.
%
Methods that mutate the \cpi{} during peeling cannot reuse it for hierarchy emit and need a second clique-enumeration pass~\cite{nucleusSariyuce14}.

\stitle{Empirical cost.}
We compare four algorithm variants on four representative graphs, sweeping $s\in\{3,5,7,9,11,13,15\}$ (Table~\ref{tab:buildhier}):
\textbf{\spinStar{}} (static-\cpi{} peel, no hierarchy),
\textbf{\spinStar{}{+}\buildHier{}} (our post-peel emit, $O(\Sig\log\Sig)$ one pass),
\textbf{\cbnd{}} (mutable-\cpi{} baseline, no hierarchy), and
\textbf{\cbnd{}{+}\textsc{Hier}} (NuclearCD's general $(r,s)$ level-DSU hierarchy specialised to $r{=}1$, with one disjoint-set forest per peel level).
%
All four solve the same problem; the comparison isolates the cost of hierarchy emission and of the underlying peel strategy.
%
Three observations follow:
%
(i) \buildHier{} adds at most $1.5\times$ memory on top of \spinStar{}'s peel state, while \cbnd{+}\textsc{Hier}{} carries $K=\kmax$ parallel DSUs and blows up memory by $8$--$43\times$ over \spinStar{+}\buildHier{} on the same configuration.
%
(ii) Even \emph{without} emitting a hierarchy, \cbnd{} already uses more memory than \spinStar{+}\buildHier{} (e.g.,\ $50$\,GB vs.\ $32$\,GB on \texttt{wiki-Talk} at $s{=}7$), and at $s\ge 9$ on \texttt{wiki-Talk} both \cbnd{} variants exceed the $503$\,GB budget and never start.
%
(iii) The hierarchy build itself is cheaper than the level-DSU baseline: \buildHier{}'s emit-only time is $1.5$--$30\times$ faster than \cbnd{+}\textsc{Hier}{}'s union work across the same cells, consistent with the $O(\Sig\log\Sig)$ vs.\ $O(K\cdot\Sig)$ bounds.
