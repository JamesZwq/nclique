\section{Core-Value Hierarchy Construction}\label{sec:buildhier}

Because the static-\cpi{} invariant of Section~\ref{sec:static} keeps every leaf intact through peeling, the hierarchy is no longer a separate decomposition problem.
%
After the core values are known, every \cpi{} leaf encodes the same family of $s$-cliques both before and after the peel, so the elder-rule join tree of Definition~\ref{def:nucleus} can be emitted by a single descending union--find scan over the preserved leaves, in $O(\Sig\log\Sig)$ time, without re-enumerating a single clique.
%
Algorithms that mutate the \cpi{} during peeling cannot reuse it for this purpose: they must either re-run $s$-clique enumeration at each level or maintain one parallel disjoint-set forest per core level during peeling, which blows up memory by an order of magnitude (Section~\ref{sec:exp}, Figure~\ref{fig:hier}).
%
For any level $k$, the super-level set is $V_k=\{v\mid \kappa_s(v)\ge k\}$ and Definition~\ref{def:nucleus} measures connectivity inside $V_k$ through $s$-clique witnesses contained in $V_k$; \buildHier{} (Algorithm~\ref{alg:buildhier}) materialises that filtration from the preserved leaves.

\stitle{Leaves as connectors.}
A \cpi{} leaf $P$ encodes the family of $s$-cliques $\Vh(P)\cup X$ for every $\eta_P$-subset $X\subseteq\Vp(P)$ (Definition~\ref{def:path}).
%
Define the \emph{birth level} of $P$ as
\[
  k_P \;=\; \min_{v\in\Vh(P)\cup\Vp(P)}\kappa_s(v).
\]
%
At level $k\le k_P$ every leaf vertex has core value at least $k$, so every encoded $s$-clique is contained in $V_k$.
%
For $\eta_P\ge1$ the leaf's member set is $\Vh(P)\cup\Vp(P)$: any two members either lie inside one encoded $s$-clique (when $\eta_P\ge2$) or are linked by a length-two path through a vertex of $\Vh(P)$ (when $\eta_P=1$ and $\Vh(P)$ is non-empty); when $\Vh(P)=\emptyset$ and $\eta_P\ge2$, any pair appears together in some $s$-subset.  The boundary case $\eta_P=0$ (i.e.\ $|\Vh(P)|=s$) encodes the single $s$-clique $\Vh(P)$ itself; the leaf's member set is then $\Vh(P)$ alone, and $\Vp(P)$ vertices are not unified through this path.
%
In every case the leaf vertices form a single $s$-connected component the moment $P$ becomes active.
%
This lets \buildHier{} treat each leaf as a single hyperedge in a union--find structure: the leaf node is unified with every vertex it contains.
%
Two vertices then end up in the same component if and only if they are $s$-connected through active \cpi{} cliques at the current level.

\stitle{Reverse scan over leaves.}
\buildHier{} processes leaves in nonincreasing $k_P$, as the level descends through the filtration.
%
A union--find structure spans both vertices and leaf identifiers; processing leaf $P$ at its birth level fires unions $\textsc{Union}(P,v)$ for every $v\in\Vh(P)\cup\Vp(P)$.
%
A birth level is recorded for each component root, so a merge applies the elder rule.
%
Vertices not appearing in any leaf with $k_P\ge1$ have $\kappa_s(v)=0$ and are omitted from the hierarchy.

\begin{algorithm}[t]
\algfontsize
\caption{\buildHier{} --- elder-rule join tree from a static \cpi{}.}
\label{alg:buildhier}
\KwIn{Static \cpi{} $\mathcal{P}$; core values $\kappa_s(v)$ for every $v\in V$.}
\KwOut{Elder-rule join tree $T$ of the $s$-clique-connected super-level filtration.}

\ForEach{leaf $P\in\mathcal{P}$}{
    $k_P \gets \min\{\kappa_s(v)\mid v\in\Vh(P)\cup\Vp(P)\}$\;
}
sort $\mathcal{P}$ by nonincreasing $k_P$ (ties broken by leaf id)\;
initialise union-find $U$ over $V\cup\{P\mid P\in\mathcal{P}\}$; $\text{birth}[r]\gets+\infty$ for every root $r$\;
$T\gets$ empty forest\;
\ForEach{leaf $P$ in sorted order}{
    $M_P\gets\Vh(P)\cup\bigl(\Vp(P)\text{ \rm{if} }\eta_P\ge1\bigr)$ \tcp*{members in some encoded $s$-clique}
    $R\gets\{\textsc{Find}(x)\mid x\in M_P\cup\{P\}\}$\;
    \ForEach{root $r\in R$}{
        \If{$\text{birth}[r]=+\infty$}{
            emit a hierarchy node $n_r$ with $k_{\mathrm{birth}}\gets k_P$; $\text{birth}[r]\gets k_P$\;
        }
    }
    \If{$|R|\ge2$}{
        sort $R$ descending by $(\text{birth}[r], \text{id}(r))$; let $r^\star$ be the elder \tcp*{elder rule; ties broken by root id}
        \ForEach{$r\in R\setminus\{r^\star\}$}{
            attach $n_r$ as child of $n_{r^\star}$ at level $k_P$ in $T$ \tcp*{younger dies}
        }
        $\textsc{Union}$ all of $R$ into a single component\;
    }
}
\Return{$T$}
\end{algorithm}

Algorithm~\ref{alg:buildhier} assumes the peel has already produced the core values, then assigns each leaf its birth level $k_P$ as the minimum core value among its hold and pivot vertices (Lines~1-2).
%
Leaves are sorted by nonincreasing $k_P$ (Line~3) so they fire in descending peel order, and the union--find structure is initialised over both vertices and leaf identifiers with all roots born at $+\infty$ (Line~4).
%
For each leaf $P$ in sorted order (Lines~6-12), the algorithm collects the current root set $R$ of every vertex in $P$ together with the leaf itself (Line~7), emits a fresh hierarchy node for any root that has not been born yet (Lines~8-10), applies the elder rule when $|R|\ge2$ by selecting the earliest-born root $r^\star$ and attaching the others as its children at level $k_P$ (Lines~11-13), and finally unifies all roots into a single component (Line~14).
%
The returned forest $T$ is the elder-rule join tree.

\stitle{Correctness.}
The descending scan visits each leaf at exactly the level it first contributes $s$-cliques contained in the current super-level set.
%
At that level, every vertex it contains lies in the super-level set, so the leaf witnesses pairwise $s$-connectivity for all of them through a common element of $\Vh(P)$ (or directly within an $s$-subset when $\Vh(P)=\emptyset$).
%
Conversely, every active $s$-clique at level $k$ belongs to some leaf with $k_P\ge k$, and that leaf has already fired before the scan reaches level $k$; so every $s$-clique-connected merge of Definition~\ref{def:nucleus} is performed.
%
When two distinct components meet at a leaf, the elder rule preserves the component with earlier birth and attaches the younger one in the join tree~\cite{edelsbrunner2010topology}.

\stitle{Complexity.}
Computing every $k_P$ scans each leaf's members once, costing $O(\Sig)$.
%
Sorting the $L=|\mathcal{P}|$ leaves by $k_P$ costs $O(L\log L)$.
%
Each leaf fires at most $|M_P|\le|\Vh(P)|+|\Vp(P)|$ union-find operations, summing to $O(\Sig\,\alpha(n+L))$ across all leaves, where $\alpha$ is the inverse Ackermann function.
%
Total time $O(\Sig\,\alpha(n+L)+L\log L)$, with no clique re-enumeration: \buildHier{} reads each \cpi{} leaf at most twice (once to compute $k_P$, once to fire unions).

\stitle{Memory.}
Beyond the union-find of size $n+L$, the routine needs a list of vertices per leaf to fire unions.
%
\spinStar{}'s vertex-to-path inverse CSR (Section~\ref{sec:hindex}) supports a single bucket-CSR pass that materialises the per-leaf lists in $O(\Sig)$ temporary memory; this scratch is freed on return.
%
The static \cpi{} budget of Section~\ref{sec:exp} therefore holds throughout peeling proper and is only briefly elevated during the hierarchy emit.

\stitle{Consequence.}
The clique-coherent core-value hierarchy is not a separate decomposition problem in this pipeline.
%
It is a byproduct of the static \cpi{} surviving peeling: leaves act as hyperedges of an implicit $s$-clique witness graph, and a single descending pass with union--find produces the join tree.
%
Methods that mutate the \cpi{} during peeling cannot reuse it for hierarchy emit and need a second clique-enumeration pass~\cite{nucleusSariyuce14}.

Section~\ref{sec:exp} (Exp-7) compares \buildHier{} against the only feasible baseline at $r{=}1$ --- \cbnd{}'s general $(r,s)$ level-DSU hierarchy specialised to $r{=}1$ --- and confirms that \buildHier{} uses up to $43\times$ less memory (gmean $13\times$ over $24$ matched cells) and up to $35\times$ less hierarchy-emission wall time, with the gap growing at larger $s$ where the witness mass dominates.
