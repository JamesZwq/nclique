\section{Core-Value Hierarchy Construction}\label{sec:buildhier}

Because the static-\cpi{} invariant of Section~\ref{sec:static} keeps every leaf intact through peeling, the hierarchy is no longer a separate decomposition problem.
%
After the core values are known, every \cpi{} leaf encodes the same family of $s$-cliques both before and after the peel, so the elder-rule join tree of Definition~\ref{def:nucleus} can be emitted by enumerating one merge event per encoded $s$-clique birth from the preserved leaves and scanning those events in descending level with a union--find, in $O(\Sig\log\Sig)$ time, without re-enumerating a single clique.
%
Algorithms that mutate the \cpi{} during peeling cannot reuse it for this purpose: they must either re-run $s$-clique enumeration at each level or maintain one parallel disjoint-set forest per core level during peeling, which blows up memory by an order of magnitude (Section~\ref{sec:exp}, Figure~\ref{fig:hier}).
%
For any level $k$, the super-level set is $V_k=\{v\mid \kappa_s(v)\ge k\}$ and Definition~\ref{def:nucleus} measures connectivity inside $V_k$ through $s$-clique witnesses contained in $V_k$; \buildHier{} (Algorithm~\ref{alg:buildhier}) materialises that filtration from the preserved leaves.

\stitle{Per-clique events from each leaf.}
A \cpi{} leaf $P$ encodes the family $\{\Vh(P)\cup X\mid X\subseteq\Vp(P),\,|X|=\eta_P\}$ of $s$-cliques (Definition~\ref{def:path}).
%
A given encoded clique $\Vh(P)\cup X$ is alive in $V_k$ iff $\min_{v\in\Vh(P)\cup X}\kappa_s(v)\ge k$, so different cliques of the same leaf may first appear at different levels.
%
For each leaf we therefore generate a short ordered list of \emph{merge events} that exactly track the level at which a new encoded clique enters $V_k$.
%
Let $h_{\min}=\min_{v\in\Vh(P)}\kappa_s(v)$ (or $+\infty$ if $\Vh(P)=\emptyset$) and sort $\Vp(P)$ as $p_1,\ldots,p_m$ with $\kappa_s(p_1)\ge\cdots\ge\kappa_s(p_m)$.
%
When $\eta_P=0$ the leaf encodes the single clique $\Vh(P)$, fired at level $h_{\min}$ with member set $\Vh(P)$.
%
When $\eta_P\ge1$, the first event fires at level $k^{(\eta_P)}=\min(h_{\min},\kappa_s(p_{\eta_P}))$ and unifies $\Vh(P)\cup\{p_1,\ldots,p_{\eta_P}\}$ --- the highest-birth encoded clique.
%
For each $i=\eta_P+1,\ldots,m$ a follow-up event fires at level $k^{(i)}=\min(h_{\min},\kappa_s(p_i))$ and unifies the new pivot $p_i$ into the leaf's already-formed component (concretely with $p_1$ as anchor), because adding $p_i$ activates the encoded cliques that contain $p_i$ together with $\eta_P-1$ already-active pivots.
%
The list of events from a single leaf has length $\max(1,|\Vp(P)|-\eta_P+1)$, and the events fire at strictly nonincreasing levels.

\stitle{Reverse scan over events.}
\buildHier{} concatenates events across all leaves and processes them in nonincreasing level.
%
Each event $(k,S)$ unifies the vertices in $S$ via union--find with the elder rule (the earliest-born component absorbs the others, and each younger component dies into the elder at level $k$).
%
A vertex first appearing in some event with $k_{\mathrm{event}}\ge1$ is born at the highest level at which it is unified; vertices that never appear ($\kappa_s(v)=0$) are omitted from the hierarchy.

\begin{algorithm}[t]
\algfontsize
\caption{\buildHier{} --- elder-rule join tree from a static \cpi{}.}
\label{alg:buildhier}
\KwIn{Static \cpi{} $\mathcal{P}$ and core values $\kappa_s(v)$ for every $v\in V$, both produced by Algorithm~\ref{alg:peelH} (\spinStar{}).}
\KwOut{Elder-rule join tree $T$ of the $s$-clique-connected super-level filtration.}

$\mathcal{E}\gets[\,]$ \tcp*{merge events $(k,S)$: unify the vertex set $S$ at level $k$}
\ForEach{leaf $P\in\mathcal{P}$ with $|\Vh(P)|+|\Vp(P)|\ge s$}{
    $h_{\min}\gets\min\{\kappa_s(v)\mid v\in\Vh(P)\}$ \tcp*{$+\infty$ if $\Vh(P)=\emptyset$}
    \uIf{$\eta_P=0$}{
        append $(h_{\min},\,\Vh(P))$ to $\mathcal{E}$\;
    }\Else{
        sort $\Vp(P)$ as $p_1,\ldots,p_m$ with $\kappa_s(p_1)\ge\cdots\ge\kappa_s(p_m)$\;
        append $\bigl(\min(h_{\min},\kappa_s(p_{\eta_P})),\,\Vh(P)\cup\{p_1,\ldots,p_{\eta_P}\}\bigr)$ to $\mathcal{E}$ \tcp*{first event}
        \ForEach{$i\gets\eta_P{+}1$ \KwTo $m$}{
            append $\bigl(\min(h_{\min},\kappa_s(p_i)),\,\{p_1,p_i\}\bigr)$ to $\mathcal{E}$ \tcp*{$p_i$ joins via anchor $p_1$}
        }
    }
}
sort $\mathcal{E}$ by nonincreasing level (ties broken by event order)\;
initialise union-find $U$ over $V$; $\text{birth}[r]\gets+\infty$ for every root $r$\;
$T\gets$ empty forest\;
\ForEach{event $(k,S)$ in sorted order}{
    $R\gets\{\textsc{Find}(x)\mid x\in S\}$\;
    \ForEach{root $r\in R$}{
        \If{$\text{birth}[r]=+\infty$}{
            emit a hierarchy node $n_r$ with $k_{\mathrm{birth}}\gets k$; $\text{birth}[r]\gets k$\;
        }
    }
    \If{$|R|\ge2$}{
        sort $R$ descending by $(\text{birth}[r], \text{id}(r))$; let $r^\star$ be the elder \tcp*{elder rule}
        \ForEach{$r\in R\setminus\{r^\star\}$}{
            attach $n_r$ as child of $n_{r^\star}$ at level $k$ in $T$ \tcp*{younger dies}
        }
        $\textsc{Union}$ all of $R$ into a single component\;
    }
}
\Return{$T$}
\end{algorithm}

Algorithm~\ref{alg:buildhier} runs in two phases.  Phase~1 (Lines~1--10) generates merge events: for each leaf with at least one encoded $s$-clique, the algorithm sorts its pivot set by $\kappa_s$ in descending order and emits one event for the highest-birth encoded clique (size $|\Vh|+\eta_P$) followed by a series of unit events that each splice one lower-$\kappa$ pivot into the leaf's already-formed component.
%
Phase~2 (Lines~13--19) processes events in nonincreasing level: for each event $(k,S)$, the union--find returns the root set $R$ of $S$, emits a new hierarchy node for any root born here for the first time (Lines~15--17), and applies the elder rule to merge multiple roots into the eldest (Lines~18--22).
%
The returned forest $T$ is the elder-rule join tree of the $s$-clique-connected super-level filtration of $(V,\kappa_s)$.

\stitle{Correctness.}
Fix a level $k$ and let $C$ be any $s$-clique alive in $V_k$.
%
Uniqueness of the \cpi{} encoding (Definition~\ref{def:path}) gives the leaf $P$ such that $C=\Vh(P)\cup X$ with $X\subseteq\Vp(P)$, $|X|=\eta_P$.
%
All members of $X$ are in $V_k$, so each is among the top $|X|=\eta_P$ pivots of $P$ once $\Vp(P)$ is restricted to $V_k$; hence at the moment $C$ enters the filtration (level $\min_{v\in C}\kappa_s(v)$) the corresponding event has either already fired (if $C$ uses only the top $\eta_P$ pivots) or fires at exactly that level (when $C$ uses the new pivot $p_i$, the event $(k^{(i)},\{p_1,p_i\})$ joins $p_i$ to the leaf's component).
%
Either way the vertices of $C$ are in one component at level $\min_{v\in C}\kappa_s(v)$, so every Definition~\ref{def:nucleus} merge is performed at the correct level.
%
The elder rule preserves the component with earlier birth and attaches the younger one in the join tree~\cite{edelsbrunner2010topology}.

\stitle{Complexity.}
Phase~1 (event generation) scans each leaf once and sorts its pivot set: $O(\Sig+\sum_{P}|\Vp(P)|\log|\Vp(P)|)\subseteq O(\Sig\log L_{\max})$ ($L_{\max}$ = maximum path size, Section~\ref{sec:refresh}).
%
The number of events $|\mathcal{E}|$ is at most $\sum_P\max(1,|\Vp(P)|-\eta_P+1)\le\Sig$, and sorting them by level costs $O(\Sig\log\Sig)$.
%
Phase~2 (event processing) performs $\sum_P(|\Vh(P)|+\eta_P)+\sum_P 2(|\Vp(P)|-\eta_P)\le 2\Sig$ union-find operations in total (the first event of each leaf unifies $|\Vh|+\eta_P$ elements; each follow-up event unifies a pair), costing $O(\Sig\,\alpha(n))$.
%
Total time $O(\Sig\log\Sig)$, with no clique re-enumeration: \buildHier{} touches each \cpi{} incidence a constant number of times.

\stitle{Memory.}
Beyond the union-find of size $n+L$, the routine needs a list of vertices per leaf to fire unions.
%
\spinStar{}'s vertex-to-path inverse CSR (Section~\ref{sec:hindex}) supports a single bucket-CSR pass that materialises the per-leaf lists in $O(\Sig)$ temporary memory; this scratch is freed on return.
%
The static \cpi{} budget of Section~\ref{sec:exp} therefore holds throughout peeling proper and is only briefly elevated during the hierarchy emit.

\stitle{Consequence.}
The clique-coherent core-value hierarchy is not a separate decomposition problem in this pipeline.
%
It is a byproduct of the static \cpi{} surviving peeling: each preserved leaf contributes one merge event per encoded $s$-clique birth, and a single descending pass with union--find over those events produces the join tree.
%
Methods that mutate the \cpi{} during peeling cannot reuse it for hierarchy emit and need a second clique-enumeration pass~\cite{nucleusSariyuce14}.

Section~\ref{sec:exp} (Exp-7) compares \buildHier{} against the only feasible baseline at $r{=}1$ --- \cbnd{}'s general $(r,s)$ level-DSU hierarchy specialised to $r{=}1$ --- and confirms that \buildHier{} uses up to $43\times$ less memory (gmean $13\times$ over $24$ matched cells) and up to $35\times$ less hierarchy-emission wall time, with the gap growing at larger $s$ where the witness mass dominates.
